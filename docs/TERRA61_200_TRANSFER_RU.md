## Получить проект на другом компьютере

В PowerShell выберите каталог, в котором ещё нет папки `homensai-install-modull`,
и выполните:

```powershell
git -c core.autocrlf=false clone --branch codex/universal-installer-20261025 https://github.com/HomenSAI/homensai-install-modull.git
Set-Location homensai-install-modull
git status --short --branch
git rev-parse HEAD
git ls-remote origin refs/heads/codex/universal-installer-20261025
git rev-parse 'HEAD^{tree}'
```

Сверьте SHA HEAD с SHA ветки на сервере. Если используете существующую копию
с изменениями, не перезаписывайте и не очищайте их: сначала разберитесь с их
происхождением. При необходимости доступа используйте собственную авторизацию
GitHub на новом компьютере. Не копируйте секреты в репозиторий.

В Git сохранены план, отчёты, исходники тестовых сценариев и добавленные JSON
квитанции в `packaging/acceptance-evidence/`. Игнорируемые `.local-state/`,
локальные контейнеры и образы Docker, wheel и квитанции внутри `.git` при
клонировании не переносятся. При необходимости окружение надо восстановить по
документации проекта, сверив зависимости и версии; старые PASS не относятся
автоматически к новым артефактам или компьютеру.

## Что установлено и что осталось

* Исходные ошибки GitHub Linux CI связаны с mode 0777 исполняемого Python:
  защитная проверка корректно отклоняла файл. Исправлена только тестовая
  fixture; проверка безопасности production не ослаблялась. Run 40722287588
  на 4bc2b1f завершился успешно, однако его Python имел mode 0755.
* В run 40724824553 на 828f643 отдельный шаг с искусственным mode 0777 прошёл;
  весь run впоследствии отменён. Проверить актуальные CI результаты новой
  вершины и не объявлять этот отменённый run полным PASS.
* Installed missing-ledger прошёл в Linux DEV: после реального signed apply и
  искусственной потери ответа исходная операция осталась RECOVERY_REQUIRED,
  данные и журнал сохранены. Повторы lost-ACK и tampered-backup тоже PASS в
  описанном DEV scope. Это не проверка power-loss, SIGKILL или clean-host.
* Сверить незавершённые пункты по плану и `completed_tasks`, включая 056, 057,
  060, 069, 073, 074, 076, 077 и 086–200; условные и заблокированные пункты
  не засчитывать без доказательств. Затем продолжить оставшиеся fault профили,
  анализ восстановления и приёмочные ворота согласно самому заданию.
* `production_ready=false`, G0–G5 OPEN; отдельный Docker Git remote отсутствовал
  и имеет статус SYNC_BLOCKED. Старое двухчасовое окно закрыто; его ограничения
  и результаты не подменяют условия нового задания.
