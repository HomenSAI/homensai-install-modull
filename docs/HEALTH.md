# Проверка локального продукта

`shared.health.check_local_health(port, product_id=..., version=..., path='/health')`
предназначена для адаптеров, явно реализующих JSON-ответ ровно с полями
`product`, `release`, `healthy`. Она обращается только к `127.0.0.1` по HTTP,
отключает прокси и перенаправления, ограничивает длину ответа 16 КиБ и принимает
только HTTP 200 и точные ожидаемые публичные идентификаторы с `healthy: true`.
Неизвестные поля, повторные ключи JSON, неподходящая версия и недопустимые
входные параметры отклоняются. Таймаут относится к операциям сокета, а не к
гарантированному суммарному времени всего ответа.

Успешный ответ **не доказывает**, что слушающий процесс является нужным: другой
локальный процесс может подделать ответ. Не проверяются полномочия, процессы,
подлинность сервиса, транзакция или произвольные health-хуки. Этот формат не
навязывается всем продуктам: адаптер должен явно поддерживать его контракт.

Локальный API 1.12 предоставляет этот ограниченный тест через
`check-local-health`; он не открывает сетевой сервер и не устанавливает
продукт. Результат явно сообщает, что идентичность процесса не подтверждена.

Сквозной тест вымышленного приложения создаёт подписанные выпуски, реальные
дочерние процессы web и worker, проверяет ответ web и heartbeat worker и при
неисправном health проверяет зашифрованный откат и повторный запуск версии 1.
Тестовый управляющий код специально не выдаётся за производственный адаптер:
он управляет лишь собственными дочерними процессами, не регистрирует службы ОС,
не переживает аварийное завершение и использует динамический loopback-порт.
Windows и Docker таким тестом не приняты.
