# Криптографические зависимости: кандидат для автономной поставки

Проверка 02.11.2026. `requirements-crypto.txt` закрепляет версии и SHA-256
конкретных wheels для **обычного CPython 3.14 x86-64** на Windows и Linux с
glibc 2.28 или новее. Это кандидат зависимостей, а не готовый установщик или
заявление о приёмке обеих ОС. ARM, musl, free-threaded Python и другие версии
Python этим списком не поддерживаются. Исходные архивы и сборка из исходников
запрещены настройкой `--only-binary`; pip требует хэши всех зависимостей.

| Пакет | Версия | Лицензия в метаданных проекта | Источник |
|---|---|---|---|
| cryptography | 50.0.2 | Apache-2.0 **или** BSD-3-Clause | [PyPI](https://pypi.org/project/cryptography/50.0.2/) |
| cffi | 2.1.1 | MIT-0 | [PyPI](https://pypi.org/project/cffi/2.1.1/) |
| pycparser | 3.0 | BSD-3-Clause | [PyPI](https://pypi.org/project/pycparser/3.0/) |

В lock включены две платформенные сборки cryptography, две сборки cffi и одна
общая pycparser; полные хэши находятся в файле требований. Хэши получены из
JSON API PyPI и проверены pip при загрузке фактических wheels. В каждом из
пяти wheels обнаружены файлы лицензии проекта. Авторы cryptography сообщают,
что wheels содержат статически скомпонованный OpenSSL, а [журнал изменений](https://cryptography.io/en/latest/changelog/)
указывает OpenSSL 4.0.3 для версии 50.0.2. Лицензии встроенных компонентов,
Rust crates, уведомления и полная ведомость состава ещё требуют отдельной
проверки для распространения; одного лицензирования Python-пакета недостаточно.

Прежняя закреплённая версия 46.0.3 предшествует опубликованным исправлениям
безопасности, включая [CVE-2026-39892](https://cryptography.io/en/latest/changelog/)
и проблему [OpenSSL в wheels](https://github.com/pyca/cryptography/security/advisories/GHSA-537c-gmf6-5ccf).
Применимость каждой уязвимости к нашим вызовам отдельно не установлена.

Пример подготовки каталога на Linux x86-64 с обычным CPython 3.14:

```sh
python -m pip download --index-url https://pypi.org/simple --dest wheelhouse -r requirements-crypto.txt
python -m pip download --index-url https://pypi.org/simple --only-binary=:all: \
  --platform win_amd64 --python-version 3.14 --implementation cp --abi cp314 \
  --dest wheelhouse -r requirements-crypto.txt
```

Затем на совместимой целевой системе установка только из подготовленного набора:

```sh
python -m pip install --no-index --find-links wheelhouse -r requirements-crypto.txt
```

## Подготовка блока для общего пакета

После загрузки пяти закреплённых файлов можно подготовить новый каталог:

```sh
python -m shared.crypto_wheelhouse --source /absolute/path/wheelhouse \
  --destination /absolute/path/crypto-block
```

Инструмент не обращается к сети и не запускает содержимое wheels. Он сверяет
формат lock, версии, имена и хэши пяти файлов с закреплённым перечнем, затем
копирует wheels, два одинаковых lock-файла и известные файлы лицензий проектов.
`crypto-wheelhouse.json` содержит `lock_files` и `vendor_wheels` для поля
`runtime` манифеста v2 и перечень извлечённых лицензий. Каталог можно включить
в payload при сборке общего пакета; установленный им Python не поставляется.
Назначение должно быть новым, исходный и выходной каталоги не могут пересекаться.

При подготовке и проверке включённого криптоблока проверяются также имена и
типы всех записей внутри каждого wheel: запрещены обходы путей, абсолютные
пути, обратные слеши, повторы и конфликты имён без учёта регистра,
символические ссылки и перекрытие каталога файлом. Разрешены только обычные
файлы/каталоги и методы ZIP stored/deflate; действуют лимиты 50 000 записей
и 512 MiB суммарного распакованного размера. Проверка работает без извлечения
и повторяется для криптоблока в проверяемом пакете, включая подписанный пакет.
Она относится только к распознанному криптоблоку, а не всем wheel продукта;
она не обнаруживает произвольный вредоносный код и не проверяет происхождение.

Отдельный API 1.48 `audit-signed-wheels` применяет ту же структурную проверку
ко всем именам `.whl` внутри подписанного пакета без извлечения и запуска.
Он проверяет подпись ключом вызывающей стороны, но не является обязательным
шагом всех установочных сценариев. Кроме ограничений вложенного ZIP, допустимы
не более 128 wheels, 64 MiB на файл и 256 MiB суммарно. Формат wheel целиком,
совместимость, лицензии и вредоносный код не проверяются.

Если запись прерывается после создания служебного маркера
`.homensai-crypto-incomplete`, каталог считается незавершённым; при сбое
самого создания маркера может остаться пустой или частичный каталог без него.
Успешное завершение команды и проверка итогового пакета обязательны, одно лишь
отсутствие маркера не подтверждает готовность. Подготовка не удаляет файлы
пользователя и не перезаписывает существующее назначение. Проверки путей не
дают гарантии против одновременной подмены каталогов процессом с теми же правами.
Сборщик общего ZIP и его проверка отклоняют наличие этого маркера на любом
уровне payload, включая изменение регистра имени.

Перед удалением маркера сборщик блока перечитывает результат и сверяет все
известные wheels, оба lock-файла, лицензии и описание; посторонние файлы и
каталоги отклоняются. Отдельная проверка доступна через
`shared.crypto_wheelhouse.verify_wheelhouse(absolute_path)` и может обнаружить
неполный блок даже без маркера. Сборщик общего ZIP автоматически вызывает её,
если встречает `crypto-wheelhouse.json`. Имя зарезервировано для этого блока;
располагайте его в отдельной папке payload, а пути lock/wheel из описания
дополняйте относительным префиксом этой папки. Если при аварии отсутствуют и
маркер, и описание блока, автоматическое обнаружение по имени невозможно;
проверяйте успешное завершение подготовки и явно заданный источник. Повторная
проверка не является защитой от изменения файлов процессом с теми же правами.

02.11.2026 в одноразовом контейнере Python 3.14 загружены все пять файлов,
подготовлен блок и извлечены девять файлов лицензий проектов; затем зависимости
установлены из блока без сети и проверена операция подписи Ed25519. Windows-wheels
проверены по хэшу и составу, но не исполнялись в Windows. Реальные файлы не
добавлены в репозиторий. Это не проверка полной лицензии встроенного OpenSSL и
Rust-компонентов, provenance, наличия вредоносного кода или готовности выпуска.

Дополнительно выполнен сквозной Linux-тест в контейнере **без сети**: из пяти
ранее загруженных wheels создан блок, он включён в пакет с вымышленным продуктом,
пакет подписан временным ключом, проверен и извлечён в новый каталог. Из
извлечённого блока выполнена установка с `--no-index`, затем в отдельном Python
запущена операция Ed25519. Изменённый после подписи пакет отклонён при проверке
и подготовке. Адресные проверки сборки, подписи, подготовки и блока: **45 passed**.
Тест запускается только при наличии `HOMENSAI_CRYPTO_WHEELS`, указывающего на
заранее подготовленный каталог; Python 3.14 и закреплённые зависимости нужны
самому тесту. Для доказательства offline его следует выполнять с отключённой
сетью. Реальная установка продукта и работа на Windows этим не проверяются.

При запуске операций подписи и шифрования модуль дополнительно проверяет
метаданные версий всех трёх пакетов и отказывает, если хотя бы одна версия не
совпала. Он не устанавливает и не обновляет пакеты автоматически. Эта проверка
не пересчитывает хэши установленных файлов и не защищает от подмены метаданных
или кода с теми же правами.

Хэши не заменяют доверенный канал и проверку издателя. PyPI публикует сведения
о provenance для cryptography, но здесь их криптографическая проверка не
проводилась; у выбранных cffi wheels на PyPI нет provenance. Wheels не добавлены
в репозиторий или готовый установочный комплект. Автоматического сканирования
уязвимостей, закрепления сборочной среды и полной поставки лицензионных уведомлений
ещё нет. Windows-wheels загружены и проверены по хэшу, но не запускались на
Windows в этом исследовании. Проверку актуальности версий и бюллетеней нужно
повторять перед каждым выпуском.
