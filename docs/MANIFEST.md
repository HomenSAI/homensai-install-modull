# Манифест продукта, версия 1

© 2026 Serhii Khomenko · HomenS.AI

Манифест отделяет параметры продукта от общего механизма установки. На шаге 1
реализованы проверка JSON и формирование Docker-заготовок. Установка, архивирование,
миграции, восстановление и откат пока **не реализованы**.

Контракт: [shared/manifest.schema.json](../shared/manifest.schema.json).
Пример: [examples/jobpilot.manifest.json](../examples/jobpilot.manifest.json).
Происхождение: [PROVENANCE.md](PROVENANCE.md).

| Поле | Контракт v1 |
|---|---|
| `schema_version` | Целое число `1`; изменение несовместимого контракта требует новой версии. |
| `product_name` | Название, 1–128 символов, без управляющих символов и крайних ASCII-пробелов. |
| `product_id` | Стабильный ID, 1–63 символа: первая буква/цифра `a-z0-9`, далее также `_` и `-`. Используется для Compose project/image; не является идентификатором отдельной установки. |
| `port` | Целое число 1024–65535, одинаковое внутри контейнера и на хосте. Приложение должно само слушать этот порт на интерфейсе контейнера, доступном Docker. |
| `data_home_env` | Имя переменной окружения продукта: `[A-Z][A-Z0-9_]*`, до 128 символов. Значение в контейнере — `/data`. |
| `migration_command` | Непустой массив argv, до 64 непустых строк по 4096 символов, без управляющих символов. Проверка и рендер не исполняют эту команду. |
| `healthcheck_url` | `http://127.0.0.1:<port>/<path>` внутри контейнера. Путь содержит только ASCII-буквы, цифры и `/_.~-`; query, fragment, credentials, redirect и proxy не допускаются. Успех — HTTP 200. |
| `archive_before_replace` | Обязательное логическое `true`: отключение полного архива контрактом запрещено. Это декларация требования, не доказательство наличия архива. |
| `docker.base_image` | Ссылка на Linux Python-образ, обязательно с `@sha256:` и 64 шестнадцатеричными символами нижнего регистра. Зависимости продукта должны быть подготовлены в образе заранее. |
| `docker.start_command` | Массив argv по тем же ограничениям, что и миграция; попадает в Docker `CMD` без shell. |

Все поля обязательны; неизвестные поля запрещены, в том числе внутри `docker`.
JSON должен быть UTF-8 (BOM допускается); повторяющиеся ключи, NaN и Infinity
отвергаются. CLI возвращает `0` при успехе и `2` при ошибке входных данных.

Проверяющий модуль использует только stdlib Python 3.14+ и читает локальную схему;
это реализация набора ключевых слов этой фиксированной схемы, а не универсальный
JSON Schema engine. Дополнительные семантические проверки: порт URL совпадает с
`port`; `data_home_env` не равен `PATH`, `HOME`, `TMPDIR`, `PYTHONHOME`, `PYTHONPATH`,
`PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED`, `LD_PRELOAD`, `LD_LIBRARY_PATH`.
Они выполняются Python-валидатором сверх схемы. Целочисленные поля принимают только
JSON integer (`8765.0` и `true` отвергаются). Значения из ошибочного манифеста
не включаются в диагностические сообщения.

Проверка из корня репозитория:

```powershell
py -3.14 -B -m shared.manifest examples/jobpilot.manifest.json
```

Рендер в новый явно выбранный каталог:

```powershell
py -3.14 -B -m shared.render_docker examples/jobpilot.manifest.json --output-dir build/jobpilot
```

Появятся `Dockerfile` и `compose.yml`. Существующие файлы с такими именами
не перезаписываются. Сеть, Docker, архивы и команды продукта не вызываются.
API `validate_manifest()` возвращает независимую копию словаря;
`render_docker()` возвращает словарь с двумя текстами без записи файлов.

Dockerfile использует UID/GID `10001:10001`, `/app` для программы, `/data` для
постоянных данных и exec-form CMD/healthcheck. При сборке `/data` получает владельца
10001 и режим 0700. Compose задаёт `read_only: true`, один именованный том
`data:/data`, публикацию `127.0.0.1:<port>:<port>`, `restart: unless-stopped`,
`cap_drop: [ALL]`, `no-new-privileges` и HTTP healthcheck со стартовой паузой 60 с.
Нездоровое состояние само по себе не перезапускает контейнер: restart policy
применяется к завершению процесса. Read-only корень обеспечивается именно Compose;
отдельный `docker run` должен задать аналогичные ограничения.

В каталоге результата перед будущей сборкой потребуется подготовленный `payload/`
с кодом и публичными ресурсами продукта, без секретов и пользовательских данных.
`COPY` сохраняет владельца кода root; приложение не должно писать в `/app`.
Базовый образ должен содержать `python`, POSIX shell, `mkdir`, `chown`, `chmod`,
все рабочие зависимости, не объявлять дополнительные VOLUME и не требовать
root при старте. Унаследованный ENTRYPOINT сбрасывается. Digest в примере взят
из JobPilot Dockerfile; его существование, содержимое и пригодность здесь не
проверялись. Новых сетевых проверок или загрузок не было.

Единый том обобщает контракт DataHome JobPilot: будущий адаптер продукта должен
размещать в нём `data`, `documents`, `configuration`, `secrets`, `history`,
`installation`. Эти каталоги сейчас не создаются; legacy-пути `/backups`,
`/documents`, `/run/secrets`, bootstrap/runtime.env и ACL/DPAPI не адаптированы.
Значение `JOBPILOT_DATA_HOME` в примере обозначает **контейнерный** корень;
в исходном JobPilot это также настройка хостового bootstrap. Пример не является
совместимой заменой нынешнего установщика JobPilot.

Порт 8765 и команда `backend.cli migrate` в примере демонстрационные:
наличие такой команды не подтверждено шестью разрешёнными исходниками.
`backend.main` и `/health/ready` взяты из исходников. Зависимости JobPilot
не включены в базовый Python-образ; без их подготовки приложение не запустится.
Запись временных файлов при read-only корне потребует поддержки продукта
внутри `/data`; дополнительных томов/tmpfs этот шаг не добавляет.

Перед будущей заменой потребуется остановить всех писателей, создать и проверить
полный архив, затем выполнить миграцию и healthcheck; при сбое восстановить
согласованное состояние. Ни миграция в ENTRYPOINT, ни автоматическая замена данных
в данный шаг не входят. Архив в том же DataHome не заменяет внешнюю резервную копию.
Несколько экземпляров, владение процессами, блокировки, перенос данных, Windows,
Linux native и install/update/restore/rollback остаются следующими этапами.

Тесты pytest работают без сети; файлы сценариев создаются только через `tmp_path`.
Команда для имеющего pytest Python (кэш и bytecode отключены):

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
py -3.14 -B -m pytest -q -p no:cacheprovider --basetemp .test-tmp
```

Это локальная проверка контракта и текстов. Требуемые CLAUDE.md проверки в Docker
остаются отдельной приёмкой; разрешённый доступ к Docker Engine необходим для них.

В данной Windows-песочнице штатный tmpdir plugin pytest создал недоступный для
следующих операций `.test-tmp` (`WinError 5`). Полный набор был выполнен следующей
командой: временная fixture с тем же именем `tmp_path` создаёт каталоги с обычным
наследованием прав внутри worktree, не изменяя ACL и не отключая файловые тесты.
Для повторения этой проверки из PowerShell:

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
@'
from pathlib import Path
import uuid
import pytest

class WorkspaceTemps:
    @pytest.fixture
    def tmp_path(self):
        path = Path.cwd() / 'build' / 'manifest-pytest' / uuid.uuid4().hex
        path.mkdir(parents=True)
        return path

raise SystemExit(pytest.main(['-q', '-p', 'no:cacheprovider', '-p', 'no:tmpdir'], plugins=[WorkspaceTemps()]))
'@ | py -3.14 -B -
```

Фактическая итоговая строка полного запуска: `94 passed in 3.96s` (код 0).
Каталоги `build/` и `.test-tmp/` исключены из Git; недоступный `.test-tmp`
не удалялся и его права не исправлялись.
