# Веб-страницы: сборка и установка без командной строки

© 2026 Serhii Khomenko · HomenS.AI

Две страницы в браузере повторяют команды из [KIT.md](KIT.md) и выполняют тот же код:

| Страница | Где работает | Что делает |
|---|---|---|
| **Сборщик комплектов** | Docker-контейнер у издателя (`docker/builder`) | подключить проект, создать ключ подписи, скачать зависимости, собрать и проверить комплект, скачать архив |
| **Установщик** | сам комплект на целевом компьютере (`setup-web.cmd`, `setup.sh web`) | установка, обновление, проверка, секреты, удаление |

Установщик работает **без Docker**: Docker-контейнер не может ставить службы
Windows или systemd на компьютер, поэтому страницу поднимает встроенный Python
комплекта.

## 1. Сборщик в Docker

Нужен Docker Desktop (Windows) или Docker/Podman (Linux). Из корня модуля
установки:

```sh
docker compose -f docker/builder/compose.yml up -d --build
docker compose -f docker/builder/compose.yml logs builder
```

В журнале будет строка `Сборщик HomenS.AI: http://127.0.0.1:8790/#t=…`:
откройте её в браузере. Токен из адреса запоминается во вкладке. Если вы
открыли страницу без него, введите токен в форме входа. Постоянный токен
можно задать в `docker/builder/.env`: `HOMENSAI_BUILDER_TOKEN=` и от 24 до 128
символов `A-Z a-z 0-9 _ -`.

Каталоги на хосте (по умолчанию рядом с `compose.yml`, иначе задаются в `.env`):

| Переменная | Каталог в контейнере | Что лежит |
|---|---|---|
| `HOMENSAI_PROJECTS` | `/work/projects` | проекты продуктов, каждый в своём подкаталоге (например, копия Rent) |
| `HOMENSAI_KEYS` | `/work/keys` | ключи подписи издателя; закрытый ключ не покидает этот каталог |
| `HOMENSAI_OUTPUT` | `/work/output` | готовые комплекты (`*.tar.gz` и распакованные каталоги) |
| `HOMENSAI_BUILDER_PORT` | — | порт страницы на 127.0.0.1, по умолчанию 8790 |

Порядок работы на странице:

1. **Ключи подписи → Создать ключ** (один раз). Задайте пароль ключа и
   сохраните отпечаток: его вы публикуете для пользователей.
2. **Подключить проект**: выберите подкаталог проекта, укажите ID, название и
   порт. Будут созданы `homensai-kit.json` и шаблон манифеста. Lock-файлы,
   архивы Python Build Standalone и WinSW кладутся в проект вручную
   ([KIT.md, раздел 1](KIT.md#1-подключение-проекта)). Пока чего-то не
   хватает, в строке проекта видно, чего именно.
3. **Скачать зависимости** — wheels по lock-файлам (нужна сеть).
4. **Собрать комплект**: проект, версия, ключ и его пароль. Для нечисловой
   версии (`1.5.0-rc1`) укажите порядковый номер (`1.4.9`): по нему
   установщик отклоняет понижение версии.
5. **Готовые комплекты → Проверить** — проверка подписи и `SHA256SUMS` с
   ожидаемым отпечатком ключа. **SHA-256 архива** — для публикации. Кнопка
   **Скачать** отдаёт архив, а те же файлы лежат в каталоге `output`.

Одновременно выполняется одна команда; её вывод виден в «Журнале команды».

**Защита сборщика**

- Порт публикуется только на `127.0.0.1`.
- Запросы без токена отклоняются, как и запросы с чужим заголовком `Host` или `Origin`.
- Проект, ключ и комплект выбираются только из перечней, которые сервер составил сам; пути из браузера не принимаются.
- Пароль ключа передаётся команде через переменную окружения и нигде не сохраняется.
- Контейнер работает от непривилегированного пользователя с корнем только для чтения, без capabilities.
- Базовый образ закреплён по SHA-256, cryptography ставится по хэшам `requirements-crypto.txt`.

Rootless Podman на Linux: добавьте `--userns=keep-id`, чтобы файлы в томах
принадлежали вам.

## 2. Установщик в браузере

**Windows.** Распакуйте комплект и дважды щёлкните `setup-web.cmd`.
Windows попросит права администратора: службы ставятся от LocalSystem. Откроется
консоль с адресом страницы, а затем сам браузер. Не закрывайте консоль, пока
работаете со страницей.

**Linux.** `./setup.sh web` из каталога комплекта (обычный пользователь, как
и для остальных команд).

На странице:

- **Комплект** — продукт, версия, платформы и отпечаток ключа издателя. Сверьте
  его с опубликованным значением. Подпись проверяется перед любыми
  изменениями, как и в командной строке.
- **Установка на этом компьютере** — состояние, версия, каталог, путь к
  сохранённому установщику.
- Вкладки **Установка**, **Обновление**, **Секреты**, **Удаление**,
  **Проверка**. Параметры те же, что у команд (`--root`, режимы, ожидаемый
  отпечаток, смена ключа, `--allow-downgrade`, `--purge`).
- **Ход выполнения** — вывод установщика. Когда установщику нужен ответ,
  ниже появляется вопрос: подтверждение (кнопки «Продолжить» / «Отмена»),
  пароль архива (дважды), секреты продукта (пусто — пропустить или создать
  автоматически), ID продукта для полного удаления.

Обновление надёжнее запускать сохранённым установщиком. Его путь показан на
странице: `…\installer\setup-web.cmd` на Windows, `…/installer/setup.sh web`
на Linux. В разделе «Открыть другой комплект» укажите каталог новой версии:
подменённый комплект будет отклонён до изменений.

**Защита установщика**

- Сервер слушает только `127.0.0.1` на случайном порту.
- Адрес содержит случайный токен сеанса (256 бит) во фрагменте `#t=…`: фрагмент не уходит на сервер и в `Referer`. После загрузки токен убирается из адресной строки.
- Каждый запрос `/api/` несёт токен в заголовке `X-HomenSAI-Token`. Чужой сайт не может его задать: CORS сервер не отвечает. Неверный `Host` или `Origin` отклоняется, это защита от DNS rebinding.
- Строгий CSP без inline-кода, `no-store`, страницу нельзя встроить во фрейм.
- Пароли и секреты не попадают в журнал и не хранятся после передачи установщику.
- Одновременно выполняется одна команда; установщик по-прежнему берёт блокировку `setup.lock`.
- Сервер завершается кнопкой «Завершить работу страницы», по Ctrl+C или через 2 часа без запросов. Ответа на вопрос он ждёт 30 минут, затем операция отменяется.
- Файлы страницы (`shared/web`, `shared/kit_web.py`, `shared/web_ui.py`) и `setup-web.cmd` входят в подписанный перечень файлов установщика ([KIT.md, раздел 5](KIT.md#5-сборка-и-проверка)).

## 3. Оформление

Оформление написано с нуля по идеям стиля HomenS.AI, код стиля не
копировался:
- смысловые токены цвета, светлая и тёмная тема (системная или выбранная);
- статус всегда со знаком и словом, а не одним цветом;
- карточки и вкладки, без внешних адресов и шрифтов;
- русский, английский и немецкий языки.

Файлы: `shared/web/hsi.css`, `common.js`, `lang.json`.

## 4. Проверки

- Тесты:
  - `tests/test_kit_web.py`: вопросы и ответы, установка, обновление с паролем архива, проверка и удаление через API, отказы HTTP-защиты, CSP, отсутствие inline-кода, полнота переводов, подпись файлов страницы;
  - `tests/test_kit_builder_web.py`: перечни, отказ путей вне перечней, создание ключа с паролем, подключение проекта, скачивание.
- Linux E2E (`tests/run_kit_e2e.py`): после прежнего сценария тот же цикл через страницу — установка с вводом секрета, обновление сохранённым установщиком с паролем архива, проверка, полное удаление.

## 5. Ограничения

- Страница установщика работает только локально. Для удалённого сервера нужен
  SSH-туннель (`ssh -L 8000:127.0.0.1:<порт> сервер`), а затем адрес из консоли
  с этим портом. Само значение `Host` должно остаться `127.0.0.1:<порт>`, поэтому
  совпадающий локальный порт выбирается `setup.sh web --port <порт>`.
- В `setup-web.cmd` путь к комплекту не должен содержать апостроф `'`
  (повышение прав через PowerShell).
- Скачивание через страницу сборщика держит архив в памяти браузера. Для очень
  больших комплектов удобнее брать файл из каталога `output`.
- Docker-комплект для установки (Compose-профиль продукта) по-прежнему не
  реализован ([KIT.md, раздел 9](KIT.md#9-ограничения)).
