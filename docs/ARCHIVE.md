# DataHome и полный архив перед заменой — шаг 3

© 2026 Serhii Khomenko · HomenS.AI

Реализованы библиотечные операции на stdlib Python: разрешение постоянных
путей, план переноса, полный ZIP, проверка и восстановление в отдельный пустой
каталог. K2 добавляет необязательную шифрованную оболочку (см. «Шифрование»).
**Установщик не готов.** Остановка компонентов, блокировка операции,
миграции, переключение выпуска и транзакция rollback здесь не реализованы.

## Пути и план переноса

`shared.datahome.resolve_datahome(manifest, install_root)` сначала проверяет
манифест существующим валидатором. `install_root` — явный абсолютный путь
текущей ОС. Относительные `paths` v2 привязываются к нему, абсолютные сохраняются.
Пути другой ОС не переинтерпретируются. Значения переменных не подставляются.
Никакие каталоги не создаются; проверяются метаданные существующих предков.

Для v2 возвращается неизменяемый `DataHome(product_id, app, releases, roots)`
с пятью корнями `data`, `backup`, `services`, `config`, `runtime`. Эти имена —
поля контракта, имён продуктов в коде нет. Данные не могут совпадать с
`app`/`releases`, находиться внутри них или содержать их. В отличие от
лексического валидатора манифеста, библиотека также отвергает пересечения
между постоянными корнями, корень диска, ссылки и Windows reparse points
(включая junction) в существующей части пути. Сравнение по сегментам
консервативно не учитывает регистр. `app-data` не считается дочерним `app`.

v1 не описывает хостовые `app` и `releases`. Поэтому адаптер обязан явно
передать `app_dir`, `releases_dir` и `environ={имя_из_data_home_env: абсолютный_путь}`.
Сам модуль не читает окружение процесса. Весь указанный DataHome становится
одним логическим корнем `data`; расположение продуктовых подкаталогов не
угадывается. Для совместимости адаптер должен разместить все постоянные
данные под этим корнем либо перейти на v2. Отсутствие обязательных сведений
приводит к отказу, а не к использованию каталога программы.

`relocate_plan(source, destination)` возвращает упорядоченный tuple
`Relocation(root, source, destination)`. Совпадающие пути пропускаются.
Нужны один продукт и одинаковые наборы корней. Новые пути не пересекаются
с исходными данными и исходными `app`/`releases`; существующее назначение
должно быть пустым каталогом. Это только план: ни переноса, ни редактирования
настроек, ни проверки доступности места для будущего переноса нет.

## Создание и формат ZIP

`shared.archive.build_archive(home, destination)` читает **каждый** обычный файл
во всех корнях, включая существующие резервные копии; исключений по расширению
или имени нет. Отсутствующий корень, непрочитанный файл/каталог, ссылка, reparse
point, специальный файл или неоднозначное переносимое имя приводят к отказу.
Пустые каталоги и пустые файлы сохраняются. ZIP располагается вне всех исходных
корней и `app`/`releases`; каталог назначения должен уже существовать.
В частности, новый архив нельзя записать в архивируемый `paths.backup`:
для полного снимка нужен отдельный каталог назначения.

Формат версии 1:

| Запись | Содержимое |
|---|---|
| `roots/<логическое имя>/...` | Все файлы и явные записи каталогов соответствующего корня. Абсолютные исходные пути в ZIP не записываются. |
| `manifest.json` | `format: 1`, `product_id`, сортированный список `roots`, сортированный список `directories`, сортированный по `path` список `files`. |
| `files[]` | Только `path`, размер `size` в байтах, `sha256` (64 строчные hex-цифры) каждого файла. |

Используется `ZIP_STORED` и ZIP64; сжатие и пароли не поддерживаются.
Имена записей сортируются, время ZIP фиксировано (1980-01-01), метаданные
доступа не копируются. `manifest.json` записывается последним с сортированными
ключами JSON. Для одинаковых логических путей и байтов файлов архивы побайтово
одинаковы независимо от времени изменения файлов и порядка обхода ФС.
Манифест ограничен 16 MiB; превышение приводит к отказу.

Перед записью проводится полный проход с SHA-256 и оценка свободного места:
несжатые размеры, JSON, запас на заголовки и имена ZIP, плюс 1 MiB резерва.
Недостаток места запрещает запись. Файл пишется потоками по 1 MiB в уникальный
временный файл рядом с назначением. Во время записи повторно проверяются
байты и метаданные, после неё — полный состав источников и SHA-256. Изменение
источника приводит к отказу. Затем ZIP сбрасывается через `fsync`, полностью
проверяется и публикуется через `os.link` без замены существующего файла.
Временный файл удаляется при обычном успехе/ошибке. Нужна ФС с hard links
(например, NTFS); при неподдерживаемой операции архив не публикуется.
Аварийное завершение процесса может оставить временный файл; это не
подтверждённый архив. Ошибка записи, включая ENOSPC после предварительной
проверки, не разрешает дальнейшую замену программы.

## Проверка и восстановление

`verify_archive(path, expected_product_id=None)` проверяет структуру ZIP и JSON,
отсутствие повторяющихся полей/записей и конфликтов регистра, полный состав,
CRC, размеры и SHA-256 всех файлов. Ожидаемый ID при передаче обязателен к
совпадению. Запрещены абсолютные пути, `..`, `.`, обратные слеши, потоки `:`,
управляющие символы, имена устройств Windows, конечные точки/пробелы,
symlink-записи, шифрованные записи и методы сжатия вне собственного формата.
Лишние файлы, отсутствующие родители и файлы вместо каталогов отвергаются.

`restore_archive(path, target, expected_product_id=None)` требует существующий
пустой обычный каталог без ссылок в предках. Весь архив проверяется **до первой
записи**, затем проверяется место под несжатые данные, каталоги и резерв.
Файлы открываются эксклюзивно (`xb`), `extractall` не применяется. Результат:
`target/roots/data`, `target/roots/config` и остальные архивированные корни.
Каждый записанный файл перечитывается с диска и сверяется по размеру/SHA-256.
Исходный JSON возвращается как результат, но не помещается в дерево данных.
Живые продуктовые пути не заменяются. При ошибке после начала записи частичное
восстановление остаётся для анализа; повторный вызов в него запрещён.

Пример вызова для адаптера продукта (не команда готового установщика):

```python
from shared.manifest import load_manifest
from shared.datahome import resolve_datahome, relocate_plan
from shared.archive import build_archive, verify_archive, restore_archive

# Абсолютные пути предоставляет адаптер; все писатели уже остановлены.
home = resolve_datahome(load_manifest(manifest_path), installation_root)
receipt = build_archive(home, archive_path)
verify_archive(archive_path, expected_product_id=home.product_id)
# recovery_dir уже существует и пуст; это отдельное место проверки.
restore_archive(archive_path, recovery_dir, expected_product_id=home.product_id)
```

## Границы

Вызывающий код обязан остановить всех писателей и исключить параллельное
управление/изменение исходных каталогов, архива и назначения. Повторные проверки
выявляют обычные изменения, но не создают атомарный снимок БД и не защищают от
активного изменения путей другим процессом между проверкой и открытием.
Свободное место может уменьшиться после проверки; квоты/особенности ФС могут
привести к последующей ошибке записи. При любой ошибке замена недопустима.

SHA-256 обычного ZIP обнаруживает повреждение, но не подмену вместе с его
манифестом. Для аутентификации и конфиденциальности предназначена оболочка K2
ниже; обычный ZIP сам по себе не выполняет `backup.encrypted: true`.
Управления ключами, DPAPI или исполнения `backup.cmd`/`restore.cmd` здесь нет.
Файлы обрабатываются как байты, содержимое не
журналируется и не включается в сообщения ошибок. Реальные секреты, базы,
личные документы и auth caches в ходе разработки не открывались.

Права доступа, ACL, владельцы, timestamps, xattrs, потоки NTFS, разреженность
и идентичность hard links не восстанавливаются. Обход обычных файлов не
перечисляет дополнительные потоки NTFS; архив не является образом ФС.
Поддержка ссылок/mount points, приёмка на Linux, доставка шифрованной внешней копии,
политика хранения и полный install/update/restore/rollback остаются следующими
этапами. Docker- и native-установщики этим шагом не объявляются готовыми.

## Шифрование

K2 (`shared/archive_crypto.py`) шифрует **весь** проверенный ZIP, включая
внутренний манифест, настройки, существующие копии и все постоянные корни.
Обычный `shared.archive` сохраняет stdlib-путь. Дополнение
`requirements-crypto.txt` закрепляет `cryptography==46.0.3`; хэши проверенных
артефактов, а также pins/hashes транзитивных зависимостей для целевых платформ
должен заполнить владелец. Пока это **не готовый offline hash-lock**.
Зависимости при выполнении операций не скачиваются и не устанавливаются.

Пакет импортируется лениво. Без него каждый путь шифрования/расшифровки
отказывает с русским сообщением «Шифрование недоступно: установите
необязательный пакет cryptography из requirements-crypto.txt после заполнения
владельцем хэшей». Пароль при этом не запрашивается. Обычные ZIP create,
verify и restore продолжают работать.

Формат оболочки v1 — фиксированный бинарный заголовок **86 байт**, big-endian,
`struct >8sBBIII16sIQ32s4s`, затем последовательность шифрованных блоков:

| Поле | Размер | Значение |
|---|---|---|
| magic | 8 | `HSAICRY\0` |
| version, KDF ID | по 1 | `1`, `1` (scrypt) |
| N, r, p | по 4 | `32768`, `8`, `1` |
| salt | 16 | Новые случайные байты `os.urandom` для каждого архива |
| chunk_size | 4 | Обычно 1 MiB; допустимы 4 KiB…16 MiB |
| plaintext_size | 8 | Полный размер внутреннего ZIP |
| plaintext_sha256 | 32 | SHA-256 всех байтов внутреннего ZIP |
| nonce_prefix | 4 | Новый случайный префикс |

Ключ AES-256 (32 байта) выводится через stdlib `hashlib.scrypt` из UTF-8
парольной фразы без нормализации, с `dklen=32`, `N=2**15`, `r=8`, `p=1`,
`maxmem=64 MiB`. Рабочая память scrypt — около 32 MiB плюс служебные расходы.
Читатель принимает только эти параметры: неизвестные версии/KDF, изменённые
N/r/p, недопустимые размеры блоков и более `2**32` блоков отвергаются до KDF.
`read_header(stream)` работает без cryptography, но возвращает ещё
**неаутентифицированные** метаданные.

Для блока с номером `i` (начиная с нуля) используется 12-байтовый nonce
`nonce_prefix || uint64_be(i)`. Внутри одного архива nonce не повторяются;
новый salt задаёт новый ключ следующего архива. Каждый блок шифруется
`cryptography.hazmat.primitives.ciphers.aead.AESGCM`, тег — 16 байт.
AAD: **весь заголовок || uint64_be(i) || uint32_be(длина plaintext блока)**.
Размеры блоков выводятся из заголовка, отдельных незащищённых длин нет.
Для пустого plaintext предусмотрен один аутентифицированный пустой блок,
но такой plaintext всё равно не пройдёт проверку ZIP.

Точная длина файла проверяется до KDF и временной записи. Все теги GCM,
EOF и полный SHA-256 проверяются до передачи результата вызывающему коду.
Неверный пароль, обрезанный/удалённый, переставленный, повторённый или
изменённый блок, лишний хвост и подмена заголовка приводят к отказу.
После расшифровки вызывается существующий `shared.archive.verify_archive`
с проверкой внутреннего манифеста, всех файлов и ожидаемого продукта.
Только затем разрешён `restore_archive`: до этого **в target ничего не пишется**.

API:

```python
from shared import archive_crypto

# Адаптер заранее остановил писателей и сериализовал операцию.
provider = archive_crypto.password_provider(env_var="BACKUP_PASSWORD")
archive_crypto.build_encrypted_archive(home, encrypted_path, password_provider=provider)
archive_crypto.verify_archive(encrypted_path, password_provider=provider,
                              expected_product_id=home.product_id)
archive_crypto.restore_archive(encrypted_path, recovery_dir, password_provider=provider,
                               expected_product_id=home.product_id)
```

`encrypt_archive(source_zip, destination, password_provider=...)` оборачивает
уже существующий полный проверенный ZIP. `decrypted_archive(...)` — context
manager, выдающий `(temporary_zip_path, manifest)` после всех проверок;
временный plaintext удаляется при выходе. Создание архива выполняет полную
обратную проверку расшифровки/ZIP перед атомарной публикацией через hard link
без перезаписи; скрытый запрос при этом происходит один раз.

Пароль передаётся через внедрённый callable без аргументов, возвращающий
непустой `str`. Фабрика provider читает только явно названную переменную
окружения либо запрашивает пароль через `getpass` (скрытый ввод с терминала/stdin).
Если скрытый ввод недоступен, fallback с эхом запрещён. Отсутствующая переменная
не вызывает другой запрос. Пароли, ключи и исходные исключения provider не
печатаются и не включаются в receipts/state; Python не гарантирует затирание
строк/ключей в памяти. Пароли в argv не поддерживаются; имена опций CLI точные,
без сокращений.

CLI автоматически различает оболочку и ZIP **по magic, независимо от расширения**:

```powershell
python -m shared.ctl --manifest examples/rent.manifest.json archive-create --install-root C:\CLI-Demo --archive C:\CLI-Review\snapshot.hsac --encrypt --password-env BACKUP_PASSWORD
python -m shared.ctl --manifest examples/rent.manifest.json archive-verify --archive C:\CLI-Review\snapshot.hsac --password-env BACKUP_PASSWORD --json
python -m shared.ctl --manifest examples/rent.manifest.json archive-restore --install-root C:\CLI-Demo --archive C:\CLI-Review\snapshot.hsac --target C:\CLI-Recovery --password-env BACKUP_PASSWORD
```

Без `--password-env` шифрованный путь запрашивает пароль скрыто. Параметр
`--encrypt` существует только у create. JSON receipt содержит `encrypted: true`
для оболочки; обычный ZIP — `false`. Ошибки шифрования имеют код 1.

`FilesystemPorts(..., password_provider=provider)` использует оболочку для
исходной archive, каждой backup перед миграцией и отдельной before-rollback.
Расширение — `.hsac`; durable ключи не меняются. Повторная backup проверяет
готовый файл, а restore сначала проверяет отдельную before-rollback и исходный
archive, затем восстанавливает временное дерево перед изменением живых корней.
Обычный ZIP под ожидаемым шифрованным ключом отклоняется, fallback нет.
Без provider прежний экспериментальный режим требует `allow_unencrypted=True`.
Службы, миграции и health по-прежнему внедряются отдельно.

Для create/verify/restore нужен доступный для временной записи каталог архива
вне всех живых корней. Несжатый ZIP временно хранится на диске: файлы создаются
эксклюзивно с 0600 на POSIX, каталог сборки — 0700; Windows наследует ACL каталога.
Вызывающая сторона должна предоставить защищённый локальный каталог.
Нужно место под ZIP, оболочку и временную расшифрованную проверку; создание
может одновременно занимать около трёх размеров архива, дополнительно к источникам.
Временные файлы удаляются при обычном успехе/исключении; kill/power-loss может
оставить plaintext. Удаление не является гарантированным стиранием носителя.
Видимые размер и SHA-256 plaintext в заголовке не скрываются.
Аутентификация доказывает знание пароля, не происхождение или свежесть копии;
защиты от замены целиком на старую подлинную копию нет.

Все прежние ограничения по остановке писателей, гонкам ФС, метаданным и
неатомарному восстановлению нескольких живых корней сохраняются. Ротация,
доставка/хранение паролей, DPAPI/Credential Manager, внешнее хранилище и реальная
Docker/native install/update/restore/rollback-приёмка этим шагом не выполнены.

Тесты K2: `tests/test_archive_crypto.py`. Независимо от cryptography выполняются
разбор/ограничения заголовка, scrypt, границы nonce/AAD, отказы без зависимости,
provider без эха/утечки, удаление временного файла и ZIP round-trip.
AES-сценарии явно пропускаются, когда пакет отсутствует: полный round-trip,
повреждения/пароль/порядок, недопустимый внутренний ZIP/продукт/SHA-256,
неперезапись, очистка, CLI и FS before-rollback/restore. Пропуск не считается
проверкой криптографии.

пропуска — три symlink без привилегий Windows и один Windows-путь на POSIX.
