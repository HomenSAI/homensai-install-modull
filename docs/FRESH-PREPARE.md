# Подготовка новой нативной установки

`shared.fresh_prepare.prepare_fresh_native` — экспериментальный файловый этап
для подписанного v2-пакета. Он принимает пакет, конверт подписи, доверенный
публичный ключ и ожидаемые продукт/версию, абсолютный несуществующий корень,
оценки места для семи каталогов и резерв. Корень и все продуктовые каталоги
должны быть на текущей ОС и внутри нового корня; пересечения со служебными
файлами модуля запрещены. Родитель нового корня должен существовать.

Операция проверяет подпись, декларацию текущей нативной среды и пути, создаёт
новый корень без перезаписи и журнал `.homensai-fresh.json` со статусом
`preparing`. Журнал формата 3 связывает корень, ключ, подписанный состав и цель
хэшем плана. Затем проверяет и извлекает подписанную копию, сверяет её манифест
и полный перечень хэшей с первой проверкой, повторяет предварительную проверку
путей, создаёт каталоги и размещает выпуск с указателем под файловой блокировкой.
В случае успеха журнал и результат получают статус `prepared`.
Подготовленная копия остаётся в `.homensai-control/prepared`; размещённый выпуск
является отдельной копией, поэтому для обоих требуется место. Автоматического
удаления подготовленной копии пока нет.
Статус в файле сам по себе не доказывает успешного возврата функции: сбой может
произойти после записи статуса. Его нельзя считать подтверждением установки.
Проверенный доступ к состоянию журнала по подписанному пакету предоставляется
операцией `fresh-status` в локальном API 1.7; она возвращает
`completion_verified: false` и не проверяет весь размещённый выпуск.
API 1.10 дополнительно предоставляет `verify-native-release` для сверки
файлов выпуска и указателя с подписанным пакетом; успешная проверка не
подтверждает запуск, работоспособность или завершение установки.

Это **не завершённая установка**: миграции, секреты, установка зависимостей,
службы, запуск, проверка здоровья, Docker, полноценное возобновление и API
изменения состояния ещё не реализованы в этом этапе. Пароль здесь не запрашивается
и архив не создаётся. Оценку места предоставляет вызывающий код; она не
доказывает достаточности места для всех будущих этапов. Среда видна из текущего
процесса и может отличаться от физической машины при контейнеризации/эмуляции.

Если операция прервана или завершилась ошибкой, частичный корень сохраняется.
Он не считается установленным, и повторный вызов не перезапишет его. Отдельный
`resume_fresh_native` проверяет тот же подписанный пакет, ключ, корень и цель,
журнал и полное дерево подготовленного выпуска; если копия ещё не создана,
повторно проверяет свежие пути и заново подготавливает подписанный пакет.
Первоначальный запуск и возобновление используют общую блокировку корня;
при допустимом состоянии под блокировкой повторяются размещение и запись указателя. Перед повторной записью
оценивается свободное место для выпуска и заданный резерв. Для новых данных,
неизвестного состояния, неверных файлов, изменённого выпуска, старых журналов
форматов 1 и 2 или посторонних файлов в каталогах продукта следует отказ без их
удаления. Неполные временные каталоги `.stage-*` автоматически не очищаются и
пока блокируют повтор. Неполный каталог `prepared` также блокирует повтор и не
удаляется автоматически. Авария
между созданием корня и журнала может оставить каталог без журнала; отсутствие
журнала не означает, что каталог безопасно удалять. Автоматическое удаление
не реализовано. Текущая
блокировка защищает сотрудничающие процессы, но не от другого процесса с теми
же правами; каталог родителя и ключ доверия должны быть защищены. Права, ACL,
отказ питания и реальная Windows-среда ещё не прошли приёмку.

API 1.8 предоставляет изменяющую операцию `prepare-native-release` с ключом
идемпотентности. Её журналы формата 4 дополнительно связывают ключ с хэшем
исходного запроса; прежние локальные вызовы продолжают использовать формат 3.
Существующие журналы формата 3 можно продолжать локальной функцией, но они не
считаются операциями с клиентским ключом. Подробнее — `API-DESIGN.md`.
