# Контроллер первой установки Linux user-systemd

`shared.fresh_controller.run_portable_linux_install` связывает существующие
локальные операции API: подготовку подписанного выпуска, подготовку runtime,
публикацию и загрузку переносимых user-units, первый запуск и проверку
loopback health. С API 1.31 он также доступен как `install-portable-linux`.
Это ограниченный интерфейс, не самостоятельный установочный пакет, сетевой
сервис или поддержка Windows/Docker.

Интегратор передаёт пакет и подпись, независимо доверенный открытый ключ,
публичный ID и версию, абсолютные пути установки и каталога user-units,
режимы, оценку места и резерв. Отдельный существующий рабочий каталог должен
принадлежать текущему пользователю, иметь права 0700 и не пересекаться с
установкой или каталогом units. Его родительские каталоги, Python, код
установщика, ключ и вызывающая сторона должны быть доверенными.
Каталог user-units должен существовать, принадлежать текущему непривилегированному
пользователю и не содержать пробельных символов в пути; его родители не должны
быть доступны для записи посторонним.

Нужны шесть разных 32-символьных hex-идентификаторов: `workflow_key` и ключи
`release`, `runtime`, `publish`, `load`, `start`. Интегратор обязан сохранить
их и все параметры до вызова. Журнал в рабочем каталоге привязывает действия
к подписанному манифесту, ключу и параметрам. После ошибки тот же вызов
возобновляет незавершённый шаг с прежним ключом, не повторяя завершённые шаги.
Это не означает, что каждый сбой разрешается автоматически: при `pending`
нижний порт может потребовать отдельного разбора и отклонить повтор. Изменение
входных данных с тем же ключом отклоняется. Не запускайте конкурирующие
контроллеры и посторонние процессы, управляющие той же установкой.
В новых журналах язык сообщений можно менять при повторе. Журналы формата 1,
созданные предыдущей версией контроллера, для продолжения требуют исходный язык.

```python
from examples.demo_product.installer_client import InstallerClient

# params — сохранённый запрос с доверенным ключом, путями и шестью ключами.
result = InstallerClient(timeout=600).call(
    'install-portable-linux', params, min_minor=31, language='ru'
)
```

Подпись и открытый ключ в `params` передаются в каноническом base64. После
таймаута результат действия неизвестен: автоматический повтор клиента отключён.

Проверка здоровья использует порт и путь из подписанного манифеста, ожидает
совпадения публичных полей до `min(health_wait, 30)` секунд. Она не устанавливает
принадлежность сокета процессу. Завершённый журнал при повторном вызове не
перепроверяет текущее здоровье; поэтому ответ содержит
`current_health_verified: false`, `process_identity_verified: false` и
`installation_complete: false`. Он не доказывает отсутствие вредоносного кода,
готовность всех компонентов или совместимость runtime на других системах.
Автоматического удаления/отката частичной установки нет.

Изолированная проверка: `python3 tests/run_isolated_systemd_test.py --run --fresh-controller`.
Она устанавливает
тестовые зависимости по сети и не является приёмкой пользовательской системы.
