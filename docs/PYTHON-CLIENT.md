# Экспериментальный Python-клиент установщика

`homensai-installer-client` версии `0.25.0` — локальный клиент JSON/CLI API,
не сам установщик и не сетевая служба. Версия клиента не совпадает с
minor-версией API: нужная возможность отдельно проверяется через `capabilities`
и `min_minor`.

```python
from homensai_installer_client import InstallerClient, InstallerClientError, contract_schema

client = InstallerClient(
    python_executable='/absolute/path/to/trusted/installer-python',
    api_root='/absolute/path/to/trusted/installer',
    timeout=60,
)
caps = client.capabilities()
result = client.call('validate', {'manifest': manifest}, min_minor=0, language='ru')
request_schema = contract_schema('request')
response_envelope_schema = contract_schema('response')
```

Клиент требует Python 3.14+, согласует major/minor, операции и язык, передаёт
JSON через stdin/stdout без shell, ограничивает размер ответа и не повторяет
изменяющие операции автоматически. Для архивного секрета разрешён только явно
названный канал `HOMENSAI_SECRET_*`; он доступен для `import-update-archive` и
`run-pointer-linux-update`, если `secret_env_name` совпадает с `password_env`.
Python и `api_root` должны быть доверены;
клиент не проверяет их подлинность, а установленный wheel не устанавливает
серверную часть. Старый импорт из `examples.demo_product.installer_client`
остаётся совместимым в исходном дереве.
Без `api_root` клиент ищет установщик рядом с самим пакетом и отказывает, если
его там нет; текущий каталог вызывающей программы для поиска API не используется.
Пакет включает снимок схемы запросов API 1.64 и схему общей оболочки ответов;
они доступны через `contract_schema` без дополнительных runtime-зависимостей.

В Linux можно явно передать `event_log_path='/absolute/private/events.jsonl'`
в `client.call(...)`. Клиент проверяет наличие API 1.63 и включает путь только
в целевой запрос; предварительный вызов `capabilities` не журналируется этой
опцией. Запись и неопределённый результат описаны в [API-DESIGN.md](API-DESIGN.md).
Для просмотра агрегированных событий без раскрытия содержимого файла:

```python
summary = client.call('inspect-technical-log', {'log_path': '/absolute/private/events.jsonl'}, min_minor=64)
```

Это снимок проверенной структуры, а не подтверждение подлинности или исходов
операций. Wheel 0.25.0 собран offline с setuptools 84.2.1, SHA-256
`874a18ad1e03a6d23f80240e4f41edcf8fec631c9dba1e89174626d11bfd15e9`;
установлен в отдельное окружение и вызвал API 1.64 с записью и просмотром
событий. Это локальная тестовая сборка, не подписанный выпуск; Windows и
воспроизводимость сборки не подтверждены.
Без параметра прежнее поведение сохраняется. Предыдущий wheel 0.24.0 собран offline
с setuptools 84.2.1, SHA-256
`cf9bccff92cb62088ab816b659c9a3f12226155cac0dd92a88328d857aba5e7d`.
Он установлен без сети в отдельное окружение и вызвал API 1.63 с журналом из
независимого каталога. Это локальная тестовая сборка, не подписанный выпуск;
Windows и воспроизводимость сборки не подтверждены.
Схема ответов не описывает поля `result` каждой операции, а проверка схемы
запроса не заменяет проверку совместимости и семантическую проверку сервера.
Константы `CONTRACT_API_MAJOR` и `CONTRACT_API_MINOR` обозначают версию снимка,
а не гарантируют наличие операции на конкретном хосте.

Для обновления pointer-v2 интеграция заранее сохраняет параметры подписанных
пакетов, пути, идентификаторы и ключи операции; их состав указан в
[`API-DESIGN.md`](API-DESIGN.md). Пароль передаётся только через отдельный
канал, а не в параметрах JSON:

```python
import os
from homensai_installer_client import InstallerClient, InstallerClientError

# update_params — сохранённые интеграцией параметры API 1.60.
update_params = dict(update_params, action="start", reconcile_stop_key=None,
                     password_env="HOMENSAI_SECRET_UPDATE")
os.environ["HOMENSAI_SECRET_UPDATE"] = obtain_archive_password()
client = InstallerClient(api_root="/trusted/installer", timeout=300)
try:
    result = client.call("run-pointer-linux-update", update_params, min_minor=60,
                         secret_env_name="HOMENSAI_SECRET_UPDATE")
except InstallerClientError:
    # Не повторять вслепую: проверить checkpoint отдельной операцией
    # inspect-started-pointer-update и действовать по результату проверки.
    raise
finally:
    del os.environ["HOMENSAI_SECRET_UPDATE"]
```

Пример не управляет внешними писателями и не подтверждает происхождение
ключей, Python или подписанного кода: это обязанности интеграции.
Начиная с 0.3.0 пакет также содержит необязательный Linux `CooperativeWriterLock`
для продуктов, явно поддерживающих соглашение о блокировке писателей. Этот
механизм описан в [WRITER-GUARD.md](WRITER-GUARD.md) и не останавливает процессы,
которые его игнорируют.

## Локальная проверочная сборка

Подготовьте отдельное окружение Python 3.14 с доверенным pip и заранее
проверенный wheelhouse. Файл `build-requirements.txt` фиксирует setuptools
84.2.1 и SHA-256 его официального wheel. Затем без обращения к сети:

```sh
python -m pip install --no-index --find-links /trusted/wheelhouse \
  --require-hashes --no-deps -r build-requirements.txt
python -m pip wheel --no-index --no-deps --no-build-isolation \
  --wheel-dir /absolute/output .
```

3 ноября 2026 года Linux/Python 3.14: получен и по хэшу PyPI проверен
`setuptools-84.2.1-py3-none-any.whl` SHA-256
`ca140b45d5325a9478f880e351484f62fef15f336462e449ca0c03c873d589c2`, затем
offline собран предыдущий клиентский wheel 0.1.0 SHA-256
`7d1bc18fbedaf43f61a4211b0472b42c0f88046c70f0b2eb9d5f6bac7594ae5d`.
Он установлен без сети в отдельную среду и вызвал API из независимого
каталога с пробелами и кириллицей; тестовая подмена `shared.api` не выполнилась.
Этот хэш относится только к конкретному локальному файлу: воспроизводимость,
подпись, публичная поставка и Windows пока не подтверждены.

Следующая проверочная сборка 0.2.0 на том же закреплённом инструменте имеет

Она также установлена offline в отдельное окружение; встроенные схемы совпали

Первый локальный эксперимент использовал системные setuptools 66.1.1 и wheel
0.38.4, для которых опубликованы предупреждения безопасности; он выполнялся
offline без обработки чужих пакетов и не является выпуском. Для следующей
сборки использован только setuptools 84.2.1, установленный по закреплённому
хэшу. Подлинность источника по одному хэшу не доказывается; перед выпуском
нужны проверка происхождения, актуальных уязвимостей, подпись и проверка состава.

Setuptools указан производителем как MIT; его wheel содержит и встроенные
зависимости с собственными лицензиями. Сборочный инструмент не включён в
клиентский wheel, у клиента нет внешних runtime-зависимостей. В репозитории не
обнаружен файл лицензии самого проекта: условия распространения клиента пока
не определены; выбор и добавление лицензии остаются задачей владельца.
