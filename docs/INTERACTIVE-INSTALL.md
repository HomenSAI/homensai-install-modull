# Экспериментальная интерактивная установка Linux

В доверенном исходном комплекте на поддерживаемом Linux запустите из терминала:

```sh
python -m shared.interactive_install --request-file /absolute/path/install-request.json --language ru
```

Файл JSON содержит только объект `params` операции `install-portable-linux`
из [описания API](API-DESIGN.md). Это подготовленные интегратором данные:
подписанный пакет, подпись, открытый ключ издателя, пути, режимы, оценки места
и шесть разных долговечных ключей операции. Файл не должен содержать пароли.
Сохраняйте его и используйте те же ключи после прерывания. Ключ издателя и
файл запроса нужно получить и проверить по независимому доверенному каналу:
сам факт криптографической подписи не удостоверяет издателя.

Создать такой файл из подготовленного интегратором шаблона можно командой:

```sh
python -m shared.prepare_interactive_request \
  --template /absolute/path/template.json \
  --envelope-file /absolute/path/signature.json \
  --public-key-file /absolute/path/trusted-ed25519-public.key \
  --output /absolute/path/install-request.json --language ru
```

Без редактирования шаблона те же данные можно ввести в терминале:

```sh
python -m shared.prepare_interactive_request --wizard --language ru
```

Мастер запросит идентификатор и версию продукта, абсолютные пути пакета,
установки, служб и рабочего каталога, режимы через запятую, а также оценку
места в **байтах** для каждой категории и резерв на диск. Эти оценки должен
предоставить интегратор с учётом ожидаемых данных; мастер не угадывает их.
Затем указываются файлы подписи, доверенного открытого ключа и нового запроса.
Подготовка не запускает службы; завершение ввода до конца обязательно.

Шаблон — объект `params` без полей `envelope`, `trusted_public_key`,
`workflow_key` и `keys`; остальные поля и оценки необходимого места остаются
обязанностью интегратора. Подпись передаётся в исходных байтах подписанного
envelope, открытый ключ — в виде 32 исходных байтов Ed25519. Программа проверит
запрос через API, создаст шесть случайных ключей и новый файл с правами 0600;
существующий файл не перезаписывается. Данные сначала записываются во временный
файл и публикуются целиком; при ошибке после публикации итоговый файл может
уже существовать, поэтому его необходимо проверить перед повтором. Создание
нового набора ключей не является восстановлением прежней операции. Проверка
журнала может создать служебный файл блокировки, но не запускает установку.
Входные файлы должны быть обычными файлами без ссылки в последнем компоненте;
изменение файла во время чтения приводит к отказу. Родительские каталоги и
процессы, имеющие к ним доступ, должны быть доверенными.

Программа проверяет запрос и журнал через `inspect-portable-linux-install`,
показывает продукт, выпуск, пути, режимы, SHA-256 открытого ключа и статус.
Проверка может создать файл блокировки рабочего каталога. Если показан
незавершённый шаг, он мог уже выполниться: изучите журнал и состояние прежде,
чем продолжать. Для вызова установки введите ровно `INSTALL`; иное значение,
конец ввода или прерывание отменяет вызов. Оболочка не выполняет автоматических
повторов. Контроллер может подготовить выпуск и runtime, опубликовать и
загрузить user-systemd units, запустить службы и проверить здоровье.
Предварительное чтение журнала не подтверждает пригодность всех последующих
шагов; например, проверка структуры wheel выполняется при запуске установки.

Строка об окончании означает запись в журнале, а не подтверждение текущего
здоровья или идентичности процесса. Доступны `ru`, `en`, `de` и другие полные
установленные языковые словари. Аргументы справки пока на английском языке.
Это ограниченный экспериментальный сценарий Linux; Windows, Docker,
автоматическое создание шаблона из пакета и готовность к выпуску не заявлены.

Для просмотра журнала без запуска установки и без терминала:

```sh
python -m shared.interactive_install --request-file /absolute/path/install-request.json --language ru --inspect
```

Вывод показывает состояние журнала, а при наличии — число выполненных шагов
и текущую операцию. Код 0 означает успешное чтение, в том числе если журнал
отсутствует или шаг остаётся незавершённым; он не означает готовность продукта.
Просмотр не запускает службы, но может создать служебную блокировку в рабочем
каталоге. Проверяйте последствия прерванного шага до возобновления.

Для необязательного журнала событий добавьте `--event-log /absolute/private/events.jsonl`
к команде просмотра или установки. Родительский каталог должен существовать,
принадлежать текущему пользователю и иметь права 0700; файл журнала — 0600.
Сохраняются только заранее заданные коды событий и время UTC: параметры,
пути, пароли, ответы API и содержимое ошибок не записываются. Размер ограничен
1 МиБ; перед добавлением все существующие записи проверяются по допустимой
схеме, а при заполнении или повреждённых данных запись прекращается.
Ротация не реализована. При недоступности журнала команда прерывается; если
ошибка произошла после вызова установки, действие могло выполниться, поэтому
перед повтором проверьте checkpoint. Журнал не доказывает подлинность событий,
не шифруется и требует доверенного владельца и родительских каталогов.
Тот же формат опционально доступен отдельным API-запросам с версии 1.63;
он не охватывает автоматически все вызовы и пока доступен только в Linux.
