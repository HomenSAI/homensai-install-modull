# Руководство администратора

Для кого: администратор или опытный пользователь, который получил от
интегратора подписанный установочный пакет продукта HomenS.AI и
устанавливает его на Linux. Описывает только реализованные возможности.

## Что поддерживается сейчас

| Профиль | Состояние |
|---|---|
| Linux x86-64, user-systemd, без Docker | Установка, обновление pointer-v2, откат, удаление, переустановка — экспериментально, проверено в изолированном systemd |
| Linux + Docker/Compose | Только проверка движка, подготовка подписанного Compose-файла, start/stop и health; обновления и восстановления нет |
| Windows (с Docker и без) | Генерация и синтаксическая проверка сценариев; установка не реализована |

Ничего из этого не является принятым выпуском. Пропущенные или
непроверенные сценарии не считаются работающими.

## Что нужно до установки

- Linux x86-64 с systemd пользователя (`systemctl --user` работает в вашей
  сессии) и Python 3.14 для запуска установщика.
- Подписанный пакет `*.zip`, файл подписи и 32-байтовый открытый ключ
  издателя. Ключ проверьте по независимому каналу (например, сверив SHA-256
  с опубликованным издателем): подпись удостоверяет только совпадение с ключом.
- Оценки места в байтах для `app`, `releases`, `data`, `backup`, `services`,
  `config`, `runtime` и резерв — их даёт интегратор.
- Каталог установки, которого ещё нет, каталог `~/.config/systemd/user`
  (без пробелов в пути) и рабочий каталог установщика с правами `0700`.
- Без root: установка выполняется от вашего пользователя.

## Установка

1. Подготовьте файл запроса мастером (вводит параметры и создаёт ключи
   операции):

   ```sh
   python -m shared.prepare_interactive_request --wizard --language ru
   ```

2. Сохраните полученный файл запроса — он нужен для повтора после сбоя.
3. Запустите установку и введите `INSTALL` для подтверждения:

   ```sh
   python -m shared.interactive_install --request-file /абсолютный/путь/install-request.json --language ru
   ```

4. Состояние без запуска: добавьте `--inspect`. Незавершённый шаг мог уже
   выполниться — проверьте состояние перед повтором. Повтор той же командой
   продолжает установку, не повторяя завершённые шаги.

Подробности и журнал событий — [INTERACTIVE-INSTALL](INTERACTIVE-INSTALL.md).

## Обновление и откат

Обновление выполняет интегратор через API `run-pointer-linux-update`: остановка
служб, проверенный зашифрованный полный архив, размещение нового выпуска,
копия перед каждой миграцией, миграции, переключение указателя, запуск и
проверка здоровья. При сбое — отдельная копия перед откатом, восстановление
данных, прежний выпуск и повторный запуск. Пароль архива передаётся только
через переменную окружения `HOMENSAI_SECRET_*`, имя которой указано в запросе.

Состояние начатого обновления: `inspect-started-pointer-update`. Неизвестный
результат шага автоматически не повторяется. Подробности — [UPDATE](UPDATE.md)
и [API-DESIGN](API-DESIGN.md).

## Резервные копии

- Полный архив всех постоянных корней создаётся перед каждой заменой выпуска;
  при наличии секретов он шифруется (AES-256-GCM, пароль через scrypt).
- Храните пароль архива отдельно от машины: без него восстановление
  невозможно.
- Ручные команды: `archive-create --encrypt`, `archive-verify`,
  `archive-restore` в отдельный пустой каталог — [CLI](CLI.md), [ARCHIVE](ARCHIVE.md).
- Перенос копии на новую установку: `update-import-archive` / API
  `import-update-archive` с независимо переданным SHA-256.

## Удаление и переустановка

По умолчанию удаление сохраняет данные, копии и настройки:

- просмотр без изменений — API `plan-portable-linux-uninstall`;
- удаление — `uninstall-portable-linux` с `data_policy: keep`;
- полное удаление — `data_policy: purge` и `confirm_product_id`, равный ID
  продукта; восстановить данные после этого можно только из архива.

Переустановка той же версии на сохранённых данных — повторный запуск
установки с `reuse_preserved_data: true` в тот же корень. Подробности,
проверки и ограничения — [UNINSTALL](UNINSTALL.md).

## Диагностика

- Состояние установки: `--inspect` или API `inspect-portable-linux-install`.
- Здоровье: API `check-local-health` (только `127.0.0.1`; не доказывает,
  что отвечает нужный процесс).
- Службы: `systemctl --user status <product_id>-<компонент>.service`.
- Журнал событий без секретов: `--event-log`, просмотр сводки —
  `inspect-technical-log`.
- Оценка доступа к Docker: `check-docker-engine`.

Частые коды ошибок API:

| Код | Что делать |
|---|---|
| `fresh_controller_failed` | Посмотрите `--inspect`; устраните причину (место, права, пакет) и повторите тем же запросом |
| `wheel_audit_failed` | Пакет содержит недопустимые зависимости — запросите у издателя исправленный пакет |
| `runtime_evidence_failed` | Отчёт проверки зависимостей устарел, изменён или не соответствует пакету |
| `update_run_failed` | Проверьте `inspect-started-pointer-update` до повтора |
| `update_in_progress` | Сначала завершите или откатите обновление |
| `uninstall_conflict` | Повторите удаление с прежним `operation_id` |
| `uninstall_failed` | Проверьте состояние служб и файлов; данные без явного `purge` не удаляются |
| `incompatible_api` | Версия установщика ниже требуемой клиентом |

Сообщения доступны на русском, английском и немецком; язык задаётся
`--language` или полем `language` запроса.

## Безопасность

- Не храните пароли и токены в файлах запроса, манифестах и журналах.
- Каталоги установки, рабочие каталоги и журналы должны принадлежать вам и
  иметь права `0700`/`0600`; установщик отказывает при небезопасных правах.
- Подпись и хэши не доказывают отсутствие вредоносного кода.

## Известные ограничения

- Windows-установка, Docker в обновлении и восстановлении, удаление Docker-
  установки и восстановление на другой физической машине не приняты.
- Надзор за перезапусками ограничен механизмами systemd; уведомлений нет.
- Безопасное стирание носителя при удалении не выполняется.
- Актуальное состояние проверок — [WORK-PLAN](WORK-PLAN.md).
