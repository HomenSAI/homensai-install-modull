# Как устанавливается HomenS.AI Rent

Состояние на 18.10.2026, Rent 0.4.0a3. Порядок основан на `PROJECT.md`,
решениях владельца в `INSTALL_CONCEPT.md` и действующих командах `app.ctl`.

## Три состояния установки

| Вариант | Что получает пользователь | Состояние |
|---|---|---|
| Локальная демонстрация | Рабочий стол в браузере, вымышленные данные, ручной запуск | Уже доступна: [FIRST_RUN.md](FIRST_RUN.md) |
| Пилот на Windows без Docker | Отдельный Python, данные вне программы, три автоматически запускаемые службы | Команды написаны; настоящая регистрация служб и рабочая установка ещё требуют приёмки |
| Продуктовый установщик `.exe` с Core | Пошаговая установка, вход и роли, ключи и восстановление, запуск браузера | Следующий этап после пилота; готового `.exe` в текущем выпуске нет |

**Реальные деньги и персональные данные пока не приняты:** открыты 16 денежных
дефектов и платформенная приёмка. См. [LOGIC_AUDIT-20261018.md](LOGIC_AUDIT-20261018.md)
и [COMPLETION.md](COMPLETION.md). Этот документ описывает порядок установки;
сама установка на рабочий ПК здесь не выполняется.

## Как будет выглядеть полноценная установка для пользователя

| Шаг | Что видит и выбирает пользователь | Что делает установщик | Реализовано сейчас |
|---|---|---|---|
| 1. Условия | Язык, версия программы, условия пользования, явное принятие | Сохраняет версию и контрольную сумму принятого текста | Есть тексты и требования; единого экрана установщика нет |
| 2. Где будет работать | Этот Windows-ПК либо домашний сервер | Проверяет совместимость, место, занятый порт; объясняет зависимость бота от включённого ПК | Есть конфигурация и проверки здоровья; общего мастера проверки нет |
| 3. Программа и данные | Папка программы, отдельная папка данных и место копий | Устанавливает выбранный выпуск и собственную среду; проверяет права и шифрование диска | Папки задаются в TOML, runtime готовится вручную; автоматическая проверка BitLocker в установщике не завершена |
| 4. Вход и восстановление | Первый владелец, пароль, сохранение ключа восстановления | Использует вход и роли Core, создаёт ключи, предлагает распечатать лист и подтвердить сохранение | Адаптер Core есть; полный установочный и восстановительный цикл не принят |
| 5. Telegram | Создать бота по подсказке BotFather, ввести токен, при желании выбрать приватный канал архива | Проверяет подключение, сохраняет секрет отдельно от базы и программы, выполняет явно выбранную тестовую отправку | Бот и архив есть; единый установочный экран и реальная отправка требуют приёмки |
| 6. Копии | Выбрать носитель/папку и расписание | Проверяет доступность, готовит зашифрованную копию и проверку восстановления | Автономные архив и восстановление реализованы; перенос на чистую платформенную установку не принят |
| 7. Запуск | Сводка выбранных настроек и кнопка завершения | Регистрирует механизм автозапуска, проверяет базу, миграции и здоровье компонентов | Команды служб есть; настоящая установка WinSW ещё не принята |
| 8. Первое заполнение | В браузере открывается мастер хозяйства | Сохраняет каждый шаг; после минимального заполнения открывает Рабочий стол | Веб-мастер и Рабочий стол реализованы |

Дополнительный доступ с телефона через VPN выбирается отдельно. Входящие
порты Rent по умолчанию не открываются. VPN — отдельный продукт, его установка
и подключение не завершены в установщике Rent. Telegram использует исходящие
соединения. Если ПК выключен или спит, бот и напоминания на нём не работают.

## Что заполняется после установки

1. Ситуация владельца: совладельцы, помощь родственникам, проживающие свои,
   начальные долги/переплаты. Ответы управляют необходимыми разделами.
2. Хозяйство: язык, валюта, часовой пояс, собственники и реквизиты.
3. Объекты: адрес и тип, доли, аренда, коммунальные услуги и тарифы,
   начальные показания, опись, стоимость и резервы.
4. Текущие договоры: жильцы, даты, залог, долг/аванс на начало учёта.
5. Telegram, архив и необязательные настройки.

В 0.4.0a5 в **Настройках → Фотографии объектов** задаётся отдельный каталог
снимков. Rent создаёт подпапки объектов; в карточках сохраняются пути,
доступны загрузка и локальный Проводник. Подробности — [LISTING_PHOTOS.md](LISTING_PHOTOS.md).

Можно загрузить Excel-шаблон, скопировать настройки другого объекта и
продолжить мастер позже. Индикация «готово к работе» в мастере означает
достаточность заполнения карточек; текущий аудит денежных дефектов остаётся
отдельным условием допуска реального учёта.

## Как устроена установка на диске

Пример будущей Windows-установки; выбранный диск данных должен иметь свободное
место и подходящую защиту. Это пример расположения, каталоги не создавались.

```text
C:\Program Files\HomenS.AI Rent\
    runtime\              отдельная среда Python
    app-0.4.0a3\          установленный выпуск программы
    services\             конфигурация автономных служб

C:\ProgramData\HomenS.AI Rent\
    rent.toml             несекретная конфигурация
    rent.sqlite3          база хозяйства
    HomensaiRent_Data\    PDF, фотографии, вложения

Другой защищённый носитель\HomensaiRent_Backups\
    ...                   зашифрованные копии
```

Права на программу, runtime и конфигурацию — у администратора; доступ службы
к данным настраивается отдельно. Ключи и пароли сохраняются в защищённом
хранилище/окружении служебной учётной записи. Переменные обычного пользователя
Windows могут быть недоступны службе LocalSystem.

База — SQLite: отдельный сервер базы данных устанавливать не требуется.
При первом запуске на новом пути программа создаёт схему и открывает мастер.
Существующая база проверяется перед запуском; изменение её схемы выполняется
через миграции с резервной копией.

## Что можно установить командой уже сейчас

Для вымышленного пилота администратор готовит отдельный Python 3.14 x64,
выпуск Rent, зависимости из `requirements/rent-runtime.lock` с проверкой
хэшей, папки данных, секреты и `rent.toml`. Затем из каталога выпуска:

```powershell
python -m app.ctl install --config "C:\ProgramData\HomenS.AI Rent\rent.toml"
python -m app.ctl start --config "C:\ProgramData\HomenS.AI Rent\rent.toml"
python -m app.ctl status --config "C:\ProgramData\HomenS.AI Rent\rent.toml"
python -m app.ctl doctor --config "C:\ProgramData\HomenS.AI Rent\rent.toml"
```

`python` означает интерпретатор подготовленной отдельной среды.
Полный пример TOML и команды — [INSTALL.md](INSTALL.md).

`install` проверяет подготовленные пути, скачивает закреплённый WinSW с
проверкой SHA-256 и регистрирует `HomensaiRent-Web`, `HomensaiRent-Bot`,
`HomensaiRent-Scheduler`. Python и зависимости эта команда не устанавливает.
`start` отдельно готовит схему и запускает службы; перед миграцией существующей
базы создаётся зашифрованная копия. При ошибке миграции запуск прекращается.
Автозапуск служб настроен с задержкой и работает без входа пользователя Windows.

Веб-демо запускается без Telegram. Командный контроллер сейчас запускает все
три службы: для бота нужен токен, для архивов — пароль. Режим установщика
«пропустить Telegram и включить только нужные компоненты» ещё требует завершения.

Действующий автономный веб открывается на `http://127.0.0.1:8820/` и имеет одну
локальную учётку владельца без формы входа. Для платформенного режима Rent
используется установленное колесо Core и вход `python -m app.core_server`;
разделы продукта доступны под `/rent/`. Оба режима нельзя одновременно
подключать к одной базе и одному токену бота. Соседний репозиторий Core для
запуска не нужен: версия платформы входит в подготовленный выпуск продукта.

## Обновление, восстановление и удаление

- **Обновление сейчас:** администратор передаёт подготовленный локальный
  выпуск команде `app.ctl update`. Она останавливает службы, делает копию,
  размещает новую версию рядом, применяет миграции, переключает версию и
  проверяет `/healthz`. Загрузку новых выпусков по кнопке ещё нужно завершить.
- **Откат:** при ошибке после переключения сначала сохраняется отдельная копия
  текущего состояния, затем восстанавливается предыдущее. Принятые новой версией
  записи остаются в этой копии и требуют сверки; автоматического объединения нет.
- **Восстановление:** вернуть согласованный комплект базы, файлов и ключей,
  проверить целостность и расшифровку. `app.ctl restore` восстанавливает базу;
  вложения автоархива извлекаются через `app.archive restore --data-dir` в новую
  папку. Подробности и ограничения — [BACKUP.md](BACKUP.md).
- **Удаление:** текущая команда снимает регистрацию служб и их конфигурацию;
  база, документы, резервные копии, runtime и выпуски сохраняются.

Для пилота использовать принятый владельцем вариант Windows без Docker.
Продуктовый `.exe` следует собирать после исправления денежных дефектов и
приёмки установки/восстановления, на проверенном артефакте Core.
