# Диагностика по внедрённым фактам — шаг 8b

© 2026 Serhii Khomenko · HomenS.AI

`shared/doctor.py` — чистые stdlib-функции. Они не открывают базу, не проверяют
ФС/HTTP, не читают heartbeat, архивы или окружение, не останавливают службы и
не отправляют уведомления. Достоверность фактов обеспечивает будущий адаптер.

## Контракт

```python
from shared.doctor import evaluate_health, crash_loop, rate_limit_alert

facts = {
    "now": 10000,
    "db_opens": True,
    "schema_current": True,
    "data_dir_writable": True,
    "free_disk_bytes": 2000000000,
    "min_free_disk_bytes": 1000000000,
    "components": {
        "worker": {"heartbeat_age_seconds": 60, "failure_timestamps": [9500, 9600]}
    },
    "last_archive_age_seconds": 86400,
    "archive_schedule_seconds": 86400,
}
report = evaluate_health(facts)
# {"ok": True, "exit_code": 0, "checks": [{"code": "DB_OK", ...}, ...]}
```

Все поля обязательны; дополнительные поля запрещены. `components` — непустой
набор **всех активных** компонентов, выбранных вызывающей стороной, с публичными
ID `[a-z0-9][a-z0-9_-]{0,62}`. С манифестом/режимом этот набор автоматически
не сверяется. Неизвестный возраст heartbeat/архива передаётся как `null`,
не как ноль. Время — секунды, конечные неотрицательные числа не больше 2^53;
`now` и времена падений используют одну шкалу. Интервал архива положителен.
Байты — неотрицательные целые числа; bool вместо числа запрещён.

| Проверка | Успех | Код проблемы |
|---|---|---|
| База открывается | `db_opens is True` | `DB_FAILED` |
| Схема актуальна | `schema_current is True` | `SCHEMA_FAILED` |
| Каталог доступен для записи | `data_dir_writable is True` | `DATA_DIR_FAILED` |
| Диск | свободно **строго больше** порога | `DISK_LOW` |
| Пульс каждого компонента | возраст ≤ 180 секунд | `HEARTBEAT_STALE` / `HEARTBEAT_MISSING` |
| Падения каждого компонента | меньше 3 в `[now-600, now]` | `CRASH_LOOP` |
| Подтверждённый архив | возраст ≤ интервал + 86400 секунд | `ARCHIVE_STALE` / `ARCHIVE_MISSING` |

Успешные коды: `DB_OK`, `SCHEMA_OK`, `DATA_DIR_OK`, `DISK_OK`, `HEARTBEAT_OK`,
`CRASH_OK`, `ARCHIVE_OK`. Каждый check содержит `code`, `ok`, фиксированное русское
`message`, а проверки компонента также `component`. Проверки не прекращаются
после первой проблемы; компоненты сортируются по ID. Report JSON-совместим и
детерминирован, содержит `ok`, `checks`, `exit_code`: 0 при полном успехе,
1 при любой проблеме. Неверные/неполные факты дают только `INVALID_FACTS` и код 1,
без повторения значений входа. Времена падений в будущем запрещены; список не
обязан быть отсортирован, одинаковые времена считаются отдельными падениями.

`crash_loop(timestamps, now=...)` отдельно возвращает bool. При неверном контракте
этот helper и лимитер поднимают `DoctorError` с фиксированным русским текстом.
`CRASH_LOOP` сообщает о необходимости остановки; фактического stop здесь нет.

## Лимит сигналов

```python
allowed, next_state = rate_limit_alert("worker", {}, now=10000)
# True, {"worker": 10000}
allowed, same_state = rate_limit_alert("worker", next_state, now=13599)
# False, {"worker": 10000}
allowed, next_state = rate_limit_alert("worker", next_state, now=13600)
# True, {"worker": 13600}
```

Не чаще одного сигнала за 3600 секунд **на компонент**, независимо от кода
проблемы. Первый сигнал разрешён, в том числе при now=0; другие компоненты
независимы. Отказ не сдвигает время. Откат часов подавляет сигнал до last+3600.
Входной state не изменяется, возвращается новая копия. Часы внедрены аргументом,
часы ОС не читаются. Вызывающая сторона сериализует решение/сохранение state и
постановку сигнала в очередь. Без такого durable адаптера нет межпроцессного
лимита или гарантии доставки; текущий модуль ничего не сохраняет/не отправляет.

## CLI

```powershell
py -3.14 -B -m shared.ctl doctor-eval --facts public-facts.json --json
```

`--manifest` для doctor необязателен; если указан, проходит обычную валидацию,
но состав компонентов не изменяет. Остальные команды по-прежнему требуют
манифест. `--facts` читает только явно указанный публичный JSON. Повторяющиеся
поля, NaN/Infinity и некорректный JSON отвергаются без эха входа. Вывод использует
обычный конверт ctl `{ok, code, message, data}`, report находится в `data.report`,
код процесса совпадает с report.exit_code. Неверные факты/ошибка чтения дают 1;
ошибка аргументов или небезопасный путь — 2. Текстовый режим печатает коды,
компоненты и русские сообщения. Нельзя передавать секреты или продуктовые данные.

Тесты: `tests/test_doctor.py`, вымышленные JSON в `tmp_path`, все ветви,
пороговые значения, несколько проблем, чистота и отсутствие эха ошибочных
значений, лимит/откат часов, CLI 0/1. Полный вывод pytest — в [LINUX.md](LINUX.md).
