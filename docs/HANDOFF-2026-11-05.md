## 4. Что осталось доделать

По порядку важности.

1. **Влить `kit-installer` в `main`.** Проверки, которых требуют правила
   проекта, пройдены: install, update, restore, rollback на Linux и
   Windows 10. Нужно только разрешение владельца.
2. **Подключить Rent.** Нужны адаптер и изменения раскладки Rent, они
   перечислены в [integration/RENT.md](integration/RENT.md), раздел 4. На
   Linux черновик адаптера уже работает (раздел 3.3). Затем собрать комплект
   Rent через сборщик и пройти E2E на Rent, а не на вымышленном продукте.
   Репозиторий Rent меняется только в его собственной сессии.
3. **Мастер создания установочного пакета для Windows (exe)** — запрос
   владельца от 05.11.2026. Программа запускается на Windows как обычный
   exe, не в браузере. Она по шагам спрашивает, что ставим и как ставим:
   продукт, компоненты и режимы, платформы, каталог, порт, секреты, ключ
   подписи и версию. По кнопке «Создать» мастер собирает полный подписанный
   пакет вместе с устанавливаемой программой. Подробности и открытые вопросы
   в [WORK-PLAN](WORK-PLAN.md), блок 05.11.2026. Скачивание PBS и WinSW из
   следующего пункта мастеру тоже нужно.
4. **Сборщик: входные файлы.** Архивы Python Build Standalone и WinSW пока
   кладутся в проект вручную ([KIT.md](KIT.md), раздел 1). Можно добавить их
   скачивание с проверкой SHA-256 из `docs/KIT.md`.
5. **Приёмка на настоящих системах** (шаги 94–97), а не в тестовой ВМ и
   контейнере:
   - чистые Windows 10 или 11;
   - Debian или Ubuntu;
   - восстановление из архива на другой физической машине.
6. **Docker-комплект** (шаги 79, 93). Обновление и восстановление
   контейнеров не реализованы. Есть только план Compose, start/stop и
   health ([DOCKER-ADAPTER.md](DOCKER-ADAPTER.md)).
7. **Выпуск** (шаги 99–100): версия, публикация отпечатка ключа издателя,
   инструкция для пользователя.
8. **Открытые пункты аудита:**
   - К-4: ротация и отзыв ключа издателя пока ручные;
   - Ш-6 закрыт частично: `HOMENSAI_SECRETS_FILE` оставлен.
9. **Ограничения из [KIT.md](KIT.md), раздел 9:**
   - на Windows предки корня установки проверяются только при установке, но
     не при обновлении и удалении;
   - на Windows не поддерживаются хуки `pre_start`, `health_checks`,
     `post_update`;
   - при обновлении нельзя заменить runtime или набор режимов.
10. **Мелочи:**
   - разобрать причины 41 пропущенного теста;
   - на Windows агент ВМ берёт задание примерно через 3 минуты после старта.
     Пробная Windows выключается примерно через час, поэтому прогон нужно
     запускать сразу после старта ВМ.

## 6. Как продолжить

- Тесты: `~/.cache/homensai-api31-venv/bin/python -m pytest -q --basetemp ~/.cache/hsi-pytest/<имя> tests`.
  Каталог `--basetemp` не должен лежать в `/tmp`.
- Linux E2E: `python3 tests/run_kit_e2e.py --run`. Нужен Podman, прогон
  занимает 30–60 минут.
- Windows E2E:
  1. собрать комплекты;
  2. `podman start homensai-winvm`;
  3. дождаться агента ВМ;
  4. `tests/run_kit_windows_e2e.py --run --kits ~/.cache/homensai-kit-windows-e2e/kits --timeout 3300`;
  5. после прогона `podman stop homensai-winvm`.
