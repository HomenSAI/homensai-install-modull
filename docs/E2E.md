# Локальная файловая транзакция — шаг 6

© 2026 Serhii Khomenko · HomenS.AI

`shared/adapters_fs.py` соединяет UpdatePlan с настоящей локальной ФС и
`shared.archive`. Службы, миграции, health и hooks остаются внедряемыми
эффектами. Модуль использует только stdlib, не читает окружение и не запускает
команды, процессы, Docker или сетевые проверки. **Готового установщика нет.**

## API и размещение

```python
from shared.adapters_fs import FilesystemPorts, ReleaseSource
from shared.update_plan import UpdatePlan

# manifest — явно подготовленный v2; абсолютные пути относятся к текущей ОС.
# hashes — доверенный полный dict относительный_путь -> SHA-256 каждого файла.
ports = FilesystemPorts(manifest, install_root,
    work_dir=operations_dir,
    payloads={"2.0": ReleaseSource(payload_dir, hashes)},
    effects=injected_fakes,
    allow_unencrypted=True)
result = UpdatePlan(manifest, install_root, ports,
                    release="2.0", modes=("local",)).run()
```

Создание объекта ничего не записывает. Постоянные корни и начальный выпуск
подготавливает вызывающая сторона. `release="2.0"` соответствует
`paths.releases/app-2.0`; имя `app-` добавляет адаптер. `work_dir` обязан быть
отдельным каталогом вне app/releases и всех постоянных корней, без пересечения
в обе стороны. Нельзя использовать `paths.backup`: полный архив включает
все постоянные корни, в том числе прежние копии в этом корне.

`work_dir` хранит ZIP, небольшие JSON receipts и временные деревья восстановления.
Имена ZIP/receipts — SHA-256 устойчивого ключа UpdatePlan. Команды и окружение
туда не записываются. Ключи проверяются; ссылки/reparse points, специальные
файлы, неоднозначные имена и пересечения управляющих путей запрещены.
Все эффекты вызываются под общим `operation_lock`, при остановленных писателях.
Реальную остановку и durable идемпотентность внедряемых эффектов обеспечивает
их поставщик; модуль не выдаёт успешный stop/health по умолчанию.

`ReleaseSource` содержит полный доверенный список SHA-256. Stage проверяет
точное множество файлов и байты источника, pins обоих lock-файлов и wheels,
копирует в соседний `.stage-<uuid>`, сбрасывает файлы, перечитывает всё дерево,
затем публикует каталог через rename. Пустые каталоги сохраняются. Уже
опубликованный выпуск только проверяется, не перезаписывается. При повторе
ключа payload обязан совпасть с receipt. Старый выпуск и runtime не удаляются.
Хэши подтверждают байты; настоящую полноту зависимостей, формат wheel,
совместимость Python/ОС и подпись поставщика stage не проверяет.

Pointer — JSON ровно `{"release": "2.0"}` в manifest.update.pointer_file,
относительно services. Используется тот же механизм, что для update.json:
соседний уникальный файл → flush/fsync → os.replace, на POSIX также fsync
каталога. Повтор после публикации до receipt безопасно записывает тот же
указатель. update.json сохраняет и проверяет существующий UpdatePlan;
файловый адаптер не создаёт второй журнал состояния.

## Архив и откат

Backup вызывает `shared.archive.build_archive`, затем полностью проверяет ZIP
с ожидаемым product_id. Уже опубликованный ZIP того же ключа проверяется и
используется повторно: снимок не создаётся заново после миграции. Разные фазы
archive, backup перед миграцией и before_rollback имеют отдельные файлы.
Публикация архива требует hard links. `backup.cmd` и `restore.cmd` не исполняются.

**Шифрования нет.** Схема v2 требует `backup.encrypted: true`; stdlib ZIP этого
обязательства не выполняет. Поэтому конструктор по умолчанию отказывает;
`allow_unencrypted=True` — явное разрешение локального эксперимента, не заявление
о выполнении продуктового контракта. Реальный зашифрованный backup-порт ещё нужен.

Restore независимо проверяет отдельный ZIP `<transaction>/before_rollback`
до изменения живых данных. Затем проверяет исходный archive и точный набор
корней, извлекает через `shared.archive.restore_archive` в новый пустой каталог
и повторяемо приводит живые корни к этому снимку. Файлы заменяются атомарно,
лишние файлы/каталоги удаляются, пустые каталоги восстанавливаются, итоговые
байты и состав перечитываются. Переключение нескольких корней целиком не
атомарно: при crash писатели остаются остановленными, следующий run повторяет
restore. Receipt записывается только после проверки всех корней.

Текущие update.json, operation.lock, pointer и их родительские каталоги в services
сохраняются. Исторические версии этих файлов остаются в ZIP, но не накрывают
управляющий процесс. Старый pointer возвращается только фазой pointer_back.
Ошибка обязательной before-rollback запрещает restore, pointer_back и запуск.
Неудачные/частичные staging и restore-каталоги сохраняются для анализа;
автоматической очистки или retention policy нет.

## Блокировка и stale

`operation_lock` использует один постоянный inode и неблокирующий OS lock:
msvcrt на Windows, flock на POSIX. Файл никогда не удаляется. Метаданные содержат
только version/status/pid; их читают **после** получения OS lock. Если прежний
status был held либо запись оборвана, context manager возвращает `stale=True`.
После штатного выхода пишет released. После реальной смерти процесса OS
освобождает lock, а held остаётся. Возраст/PID не дают права отбирать живой lock;
PID здесь только диагностический. UpdatePlan возобновляет проверенный checkpoint.

На Windows блокируется байт по смещению `0x7fffffff`, вне содержимого файла:
блокировка первого байта запрещала полному архиватору читать operation.lock
через другой handle. Версии контроллеров с прежним протоколом byte-0 и новым
протоколом нельзя запускать одновременно; перед обновлением контроллера все
управляющие процессы должны быть остановлены. Сетевые ФС не поддерживаются.

## Проверки и ограничения

`tests/test_e2e_fs.py` использует только tmp_path и вымышленные файлы. Исходный
публичный `examples/jobpilot.manifest.json` остаётся v1. Fixture явно переносит
его product_id/name, порт, URL, start/migration argv и политику архива в тестовый
v2, добавляя локальные пути, режим, фальшивые lock/wheel с фактическими хэшами
и дескриптор E2E_TOKEN. Это не автоматическая миграция настоящей установки
JobPilot; продуктовые команды никогда не исполняются.

Проверяются fresh layout → архив → новый fake release → миграция-фейк →
ошибка health-фейка → отдельная before-rollback → восстановление данных и
старого pointer. Также есть успешное обновление, crash до/после каждой прямой
и обратной фазы, до/после каждого checkpoint, crash внутри публикации ZIP,
release, pointer, копирования restore и перед receipt, повтор новым экземпляром
адаптеров, отказ before-rollback, stale/live lock, pins, неизменность старого
выпуска и сохранение управляющего inode. Проверяется отсутствие синтетических
значений секретов окружения во **всех** записанных файлах, включая содержимое ZIP.
Это не redaction: полный архив намеренно сохраняет любые исходные байты;
настоящие секреты/личные документы в тестах отсутствуют и не читались.

Общая fixture запрещает сеть, новый набор дополнительно запрещает subprocess.
Crash — исключение BaseException, без настоящего kill/power-loss. Проверка
локальная на Windows; Linux, реальные службы, HTTP, миграции, шифрование,
ACL/DPAPI, mount/junction и Docker/native-приёмка не выполнялись. На Windows
fsync каталога недоступен: гарантии при потере питания зависят от ФС. Нет
защиты от злонамеренного изменения путей между stat/open и аутентификации
архивов/receipts. Распаковка и повтор restore требуют дополнительного места.

Команда `shared.ctl e2e-demo` намеренно не добавлена: подготовка явного v2 и
durable фейков уже не является маленькой обвязкой; сценарий воспроизводится
через pytest. Существующий CLI не запускает эти адаптеры.

### Воспроизведение

Используется прежняя документированная fixture WorkspaceTemps для ограничения
Windows tmpdir: обычный mkdir внутри worktree, без изменения ACL, без исключения
файловых тестов. Сторонние plugins, bytecode и кэш отключены.

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
$env:PYTHONIOENCODING = 'utf-8'
@'
from pathlib import Path
import uuid
import pytest
class WorkspaceTemps:
    @pytest.fixture
    def tmp_path(self):
        path = Path.cwd() / 'build' / 'step6-pytest' / uuid.uuid4().hex
        path.mkdir(parents=True)
        return path
raise SystemExit(pytest.main(['-q', '-r', 's', '-p', 'no:cacheprovider', '-p', 'no:tmpdir'], plugins=[WorkspaceTemps()]))
'@ | py -3.14 -B - | Tee-Object -FilePath build/step6-pytest-output.txt
exit $LASTEXITCODE
```
