# Установка: концепция двух вариантов

Черновик концепции от 12.10.2026 для решения владельца. Цель — один и тот же Rent ставится либо в контейнере, либо без него, и в обоих случаях сервер сам поднимается при включении машины, а владелец видит, что всё работает.

## 1. Что должно работать постоянно

| Компонент | Что делает | Сейчас |
|---|---|---|
| **Веб-сервер** | интерфейс на `127.0.0.1:8820` | `python -m app.web` |
| **Telegram-бот** | приём показаний, оплат, заявок; рассылки | `python -m app.bot` (long polling, входящий порт не нужен) |
| **Планировщик** | архив и бэкапы, напоминания, отчёты 1-го числа, очередь архива после счетов | Планировщик Windows раз в час |
| **Данные** | база SQLite, папка `HomensaiRent_Data` (PDF, фото), копии | на зашифрованном диске |

Общие правила для обоих вариантов:

- **Одна папка данных** вне программы (`D:\HomensaiRent\` или `/srv/homensai-rent/`): база, файлы, журналы, настройки `rent.toml`. Программу можно удалить и поставить заново — данные не трогаются.
- **Секреты** (`RENT_BOT_TOKEN`, `BACKUP_PASSWORD`, ключ шифрования полей) — не в папке программы: переменные пользователя / хранилище ОС (Windows Credential Manager, Linux — файл `0600` вне образа). Позже ключи выдаёт ядро.
- **Порядок запуска:** проверка схемы базы (миграции не применены — бэкап и `migrate up`, при ошибке — стоп с понятным сообщением) → веб → бот → планировщик.
- **Наружу ничего не открыто:** только `127.0.0.1`; доступ с телефона — бот или VPN-модуль HomenS.AI.
- **Обновление:** кнопка/команда «Обновить» → зашифрованный бэкап → новая версия → миграции → перезапуск → проверка здоровья; при ошибке — откат на прошлую версию и восстановление бэкапа одной командой.

## 2. Контроль «сервер поднялся»

Одинаково для обоих вариантов:

1. **Пульс (heartbeat).** Каждый компонент раз в минуту пишет в базу «жив, версия, время». Таблица `service_heartbeats` (без персональных данных).
2. **`/healthz`** веб-сервера: база открывается, схема актуальна, папка данных доступна, пульсы бота и планировщика не старше 3 минут, последний архив не старше расписания + 1 день, место на диске > 1 ГБ.
3. **Команда `rent status` / `rent doctor`** (модуль `app/ctl`): то же в консоли, плюс подсказки «что сделать». Код выхода 0/1 — для автоматических проверок.
4. **На главной странице** — плашка «Бот не отвечает с 10:15», «Архив не делался 9 дней».
5. **Оповещение владельцу:** если упал веб или планировщик — сообщение в Telegram от бота; если упал сам бот — уведомление Windows (toast) / письмо со стороны планировщика. Повтор не чаще раза в час.
6. **Автоперезапуск** упавшего компонента — средствами ОС или Docker (ниже); после 3 падений за 10 минут — стоп и оповещение, чтобы не крутиться в цикле.

## 3. Вариант А — контейнер (Docker)

Для домашнего мини-сервера на Linux и для будущего ядра (образ строится `FROM homensai-core:runtime`).

- **`compose.yml`**: сервисы `rent-web`, `rent-bot`, `rent-scheduler` из одного образа, `restart: unless-stopped`, `healthcheck` на `/healthz`, порт `127.0.0.1:8820:8820`.
- **Безопасность:** пользователь не root, файловая система образа только для чтения, папка данных — единственный том (`/data`, на зашифрованном диске), секреты — `env_file` вне репозитория или Docker secrets.
- **Автозапуск:** Linux — служба `docker` включена (`systemctl enable docker`), контейнеры поднимаются сами; Windows — Docker Desktop «запускать при входе» (минус: только после входа пользователя в систему).
- **Обновление:** `rent update` = бэкап → `docker compose pull` → `up -d` → проверка `/healthz` → при ошибке откат на прошлый тег образа.
- **Плюсы:** одинаковая среда везде, изоляция, простой откат по тегу, путь к ядру HomenS.AI. **Минусы:** на Windows нужен Docker Desktop + WSL2 (тяжело для обычного ПК, старт после входа), сложнее для непрограммиста.

## 4. Вариант Б — без контейнера

Для пилотной эксплуатации на ПК пользователя системы с Windows и для пользователей без Docker.

- **Установка:** установщик кладёт программу в `C:\Program Files\HomenS.AI Rent\` с собственным Python (через `uv`, версия закреплена, зависимости из `uv.lock`) — системный Python не нужен и не трогается.
- **Службы ОС вместо ручного запуска:**
  - **Windows:** три службы Windows через **WinSW** (лицензия MIT): `HomensaiRent-Web`, `-Bot`, `-Scheduler`; тип запуска «Автоматически (отложенный)», работают без входа пользователя, при сбое — перезапуск через 1 минуту. Планировщик Windows для архива больше не нужен.
  - **Linux:** юниты systemd (`rent-web.service`, `rent-bot.service`, `rent-scheduler.service`), `Restart=on-failure`, отдельный пользователь `rent`, `WantedBy=multi-user.target`.
  - **macOS:** launchd (позже).
- **Команды `rent`:** `install`, `start`, `stop`, `restart`, `status`, `doctor`, `update`, `backup`, `restore`, `uninstall` (данные не удаляет).
- **Обновление:** бэкап → новая версия рядом (`app-1.4.0`) → миграции → переключение → перезапуск служб → `/healthz`; ошибка — обратно на `app-1.3.9`.
- **Плюсы:** лёгкий, стартует при включении ПК без входа, понятен на Windows. **Минусы:** среда зависит от ОС, установщик надо поддерживать под каждую ОС.

## 5. Рекомендация

1. **Пилот сейчас — вариант Б на Windows:** службы через WinSW, `rent status/doctor`, пульс и `/healthz`, оповещения. Это нужно и для варианта А, поэтому работа не теряется.
2. **Вариант А — когда будет ядро HomenS.AI или домашний Linux-сервер:** тот же код, другой способ запуска.
3. Оба варианта — из одного репозитория и одной папки данных: переход Б → А = остановить службы, подключить ту же папку как том.

## 6. Решения владельца (12.10.2026)

- **Пилотная эксплуатация — на Windows-ПК пользователя системы**, вариант Б (службы Windows через WinSW). Бот работает, пока ПК включён.
- **Установщик `.exe` — после пилота;** на пилоте — команды `rent install / start / stop / status / doctor / update / backup / restore / uninstall`.
- **Оповещения о сбое — все три канала:** уведомление Windows, e-mail (SMTP, пароль — только в секретах) и отдельный сигнальный Telegram-бот только для сообщений «что-то упало» (свой токен `RENT_ALERT_BOT_TOKEN`), чтобы пользователь системы получил оповещение, даже если главный бот не работает. Повтор одного и того же сигнала — не чаще раза в час.
