3. Разрывы с JobPilot

Требование: `docs/handoff/NEXT-AI-START-HERE-2026-10-24.md:99` JobPilot — полный архив перед каждой заменой, legacy/DataHome/Linux/native, fresh/resume/upgrade/reinstall, перенос, ошибки миграций и rollback.

• DataHome: Rent разносит отдельные пути через TOML (`config.py:42`), но не описывает единый переносимый комплект. JobPilot уже имеет data/documents/configuration/secrets/history/installation и перепривязку bootstrap/runtime (`backend/platform/data_home.py:15`, `:44`, `:66`). Сохранить этот контракт; отдельно проверить legacy и native.
• Полный архив: update Rent сохраняет только SQLite (`operations.py:189`); документы, конфигурация служб и ключи туда не входят (`docs/INSTALL_README.md:155`). Автоархив также ограничен выбранными документами. В JobPilot `setup.ps1:1110` уже требует полный архив, проверяет результат и SHA-256 до изменения данных. Эта цепочка предпочтительнее как основа; её полную работоспособность аудит не проверял.
• Ключи/DPAPI: Rent получает пароль из окружения/HKCU (`app/archive/password.py:15`), а не из DPAPI-хранилища. Различие пользователя и LocalSystem документировано (`docs/INSTALL_README.md:292`). JobPilot уже использует DPAPI-файл пароля архива (`setup.ps1:1118`). Нужны проверки другого пользователя/ПК, текущего и предыдущего ключа, переносимого восстановления; копирование DPAPI-файла само по себе такую переносимость не доказывает.
• Миграции: полезны checksum, транзакция на миграцию и копия перед каждым шагом. Но Rent `start` не восстанавливает автоматически весь исходный снимок при сбое поздней миграции (`operations.py:40`, `:155`). Миграции и критерии совместимости должны остаться JobPilot-специфичными.
• Rollback/resume: Rent возвращает базу и указатель версии; новые записи сохраняет отдельной копией. Документы, настройки, ключи и runtime этой транзакцией не восстанавливаются. После отключения питания предусмотрено ручное восстановление, а не автоматический resume (`docs/INSTALL.md:175`). Общий runtime также не обеспечивает возврат зависимостей прежнего выпуска. JobPilot handoff:129 сообщает FAIL доступности rollback у native build2; последующее исправление отмечено только как source proof, не новая frozen-сборка.
• Владение процессами: фиксированные имена служб Rent не разделяют экземпляры. Пульс с PID не равен проверке владельца процесса; `/healthz` проверяет status без идентичности выпуска/экземпляра (`operations.py:70`). Нужны принадлежность установки, блокировка конкурирующих Docker/native-запусков, подтверждение остановки всех писателей и отказ воздействовать на чужую установку.
• ACL: WinSW XML не задаёт отдельную учётную запись или ACL; systemd задаёт User/Group и UMask, но не создаёт пользователя и права каталогов (`services.py:71`). Нет подтверждённой цепочки назначения/восстановления Windows ACL, защиты ключей и обработки носителя без нужных ACL. Fresh/resume/reinstall требуют отдельной реализации: повторный install Rent при существующих XML отказывает (`services.py:100`).
