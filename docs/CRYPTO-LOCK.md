# Криптографические зависимости: кандидат для автономной поставки

Проверка 02.11.2026. `requirements-crypto.txt` закрепляет версии и SHA-256
конкретных wheels для **обычного CPython 3.14 x86-64** на Windows и Linux с
glibc 2.28 или новее. Это кандидат зависимостей, а не готовый установщик или
заявление о приёмке обеих ОС. ARM, musl, free-threaded Python и другие версии
Python этим списком не поддерживаются. Исходные архивы и сборка из исходников
запрещены настройкой `--only-binary`; pip требует хэши всех зависимостей.

| Пакет | Версия | Лицензия в метаданных проекта | Источник |
|---|---|---|---|
| cryptography | 50.0.2 | Apache-2.0 **или** BSD-3-Clause | [PyPI](https://pypi.org/project/cryptography/50.0.2/) |
| cffi | 2.1.1 | MIT-0 | [PyPI](https://pypi.org/project/cffi/2.1.1/) |
| pycparser | 3.0 | BSD-3-Clause | [PyPI](https://pypi.org/project/pycparser/3.0/) |

В lock включены две платформенные сборки cryptography, две сборки cffi и одна
общая pycparser; полные хэши находятся в файле требований. Хэши получены из
JSON API PyPI и проверены pip при загрузке фактических wheels. В каждом из
пяти wheels обнаружены файлы лицензии проекта. Авторы cryptography сообщают,
что wheels содержат статически скомпонованный OpenSSL, а [журнал изменений](https://cryptography.io/en/latest/changelog/)
указывает OpenSSL 4.0.3 для версии 50.0.2. Лицензии встроенных компонентов,
Rust crates, уведомления и полная ведомость состава ещё требуют отдельной
проверки для распространения; одного лицензирования Python-пакета недостаточно.

Прежняя закреплённая версия 46.0.3 предшествует опубликованным исправлениям
безопасности, включая [CVE-2026-39892](https://cryptography.io/en/latest/changelog/)
и проблему [OpenSSL в wheels](https://github.com/pyca/cryptography/security/advisories/GHSA-537c-gmf6-5ccf).
Применимость каждой уязвимости к нашим вызовам отдельно не установлена.

Пример подготовки каталога на Linux x86-64 с обычным CPython 3.14:

```sh
python -m pip download --index-url https://pypi.org/simple --dest wheelhouse -r requirements-crypto.txt
python -m pip download --index-url https://pypi.org/simple --only-binary=:all: \
  --platform win_amd64 --python-version 3.14 --implementation cp --abi cp314 \
  --dest wheelhouse -r requirements-crypto.txt
```

Затем на совместимой целевой системе установка только из подготовленного набора:

```sh
python -m pip install --no-index --find-links wheelhouse -r requirements-crypto.txt
```

При запуске операций подписи и шифрования модуль дополнительно проверяет
метаданные версий всех трёх пакетов и отказывает, если хотя бы одна версия не
совпала. Он не устанавливает и не обновляет пакеты автоматически. Эта проверка
не пересчитывает хэши установленных файлов и не защищает от подмены метаданных
или кода с теми же правами.

Хэши не заменяют доверенный канал и проверку издателя. PyPI публикует сведения
о provenance для cryptography, но здесь их криптографическая проверка не
проводилась; у выбранных cffi wheels на PyPI нет provenance. Wheels не добавлены
в репозиторий или готовый установочный комплект. Автоматического сканирования
уязвимостей, закрепления сборочной среды и поставки лицензионных уведомлений
ещё нет. Windows-wheels загружены и проверены по хэшу, но не запускались на
Windows в этом исследовании. Проверку актуальности версий и бюллетеней нужно
повторять перед каждым выпуском.
