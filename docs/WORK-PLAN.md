# План доведения общего установочного модуля

Дата составления: 02.11.2026. Автор проекта: Serhii Khomenko · HomenS.AI.
Всего: 130 шагов; исходные номера 01–124 сохранены.

Уточнение владельца 02.11.2026: первая версия использует единый установочный
комплект для всех целевых систем. Разделение на минимальные комплекты не
обязательно. Профили ниже описывают совместимость продукта и выбор поведения,
а не требование выпускать отдельные пакеты. Нумерация и история сохранены.

Цель: самостоятельный общий модуль установки, проверенный на вымышленном
продукте без участия реальных проектов и зависимости от ИИ при работе.
Готовность означает выполнение требований и приёмку каждого заявленного профиля;
совместимость с реальными продуктами подтверждается отдельно после интеграции.

Статусы: `[ ]` — не начат; `[~]` — в работе; `[x]` — выполнен;
`[!]` — заблокирован. Шаг завершается только после проверки результата. При
изменении плана сохранять историю и корректировать число шагов прозрачно.

### 03.11.2026 — экспериментальный systemd-рецепт с указателем

- Чистый генератор создаёт units, вызывающие постоянный launcher с исходными
  шаблонами команд; версия в них не зашита. В одноразовом контейнере реальный
  user-systemd запустил тестовые версии 1 → 2 → 1 после изменения указателя.
- Прошли 84 связанных теста, 2 пропущены; дополнительно 7 тестов генератора
  и один изолированный тест реальной службы. Подписанный рецепт, проверенная
  доставка launcher, подключение к установщику/API, аварийное восстановление
  и полный цикл обновления пока не реализованы. Шаги 65, 67, 81 и 110 в работе.

### 03.11.2026 — основа загрузчика активного Linux-выпуска

- Добавлен отдельный экспериментальный launcher, который читает `active.json`,
  разрешает ограниченные обозначения путей и запускает выбранный процесс через
  `execv`. Проверены реальный запуск синтетических выпусков 1 → 2 → 1 и отказ
  при повреждённом указателе, ссылках, выходе за каталог и подмене при чтении.
- Прошли 256 тестов, один пропущен; после поддержки аргументов-каталогов
  повторно прошли 16 тестов launcher. Он пока не включён в установку,
  systemd units или API, не проверяет подписи и требует доверенных файлов;
  нужны интеграция и проверка полного цикла восстановления. Шаги 65, 67, 81
  и 110 остаются в работе.

### 03.11.2026 — несовместимость переносимого Linux-запуска и обновления

- Выявлено, что подписанный systemd-рецепт v1 подставляет в `@release` путь
  старой версии, а переключение указателя его не меняет. Общий план с такой
  службой мог бы запустить прежний код. Это препятствует полноценному API
  обновления непосредственно после свежей установки.
- Сборщик отклоняет новый план с точно распознанными закреплёнными units и
  продолжение прямого направления; для направления отката сборка доступна.
  Чужие и изменённые units не подтверждаются этой проверкой. Требуется отдельная
  реализация переключения служебных команд с проверкой восстановления.
- Прошли 39 тестов, один пропущен, 4 адресных сценария и 3 сценария обновления
  с systemd и отдельным тестовым launcher. Последний результат не является
  проверкой перехода между свежей установкой и обновлением. Шаги 65, 67, 81 и
  110 остаются в работе.

### 03.11.2026 — повторная проверка копии перед публикацией выпуска

  архив и его корни непосредственно перед публикацией нового выпуска. Отказ
  оставляет результат шага неопределённым: выпуск и указатель не меняются.
- Проверены отсутствие архива, подмена и неверный пароль; прошли 39 связанных

### 03.11.2026 — безымянная расшифровка при проверке и восстановлении

- Linux `verify_archive` и `restore_archive` теперь расшифровывают во временный
  `O_TMPFILE`, не создавая именованный ZIP. Реальный SIGKILL после расшифровки
  проверен для обоих путей; восстановление не начиналось до проверки архива.
- Низкоуровневый `decrypted_archive`, возвращающий путь, и системы за пределами
  Linux сохраняют именованный временный файл. Физическое стирание блоков и
  защита от аварий во всех фазах не подтверждены; шаг 70 остаётся в работе.
- Linux, Python 3.14: расширенный набор — 177 passed, 8 skipped; после
  уточнения совместимости именованного пути отдельно прошли 86 тестов шифрования.

### 03.11.2026 — безымянный исходный ZIP на Linux

- Для создания шифрованного архива исходный ZIP на Linux теперь записывается
  в безымянный файл `O_TMPFILE`; при отсутствии поддержки операция отказывает.
  Проверки состава, изменений данных и шифрованной оболочки сохранены.
- Тест с настоящим SIGKILL на этапе до шифрования подтверждает отсутствие
  именованного ZIP, освобождение блокировки и запрет повтора. Проверка и
  восстановление всё ещё расшифровывают во временный именованный файл, другие
  ОС используют прежний путь; безопасное хранение после аварии не завершено.
- Linux, Python 3.14: 163 теста архивов, шифрования, обновления и блокировок
  прошли. Это не приёмка Windows или всех файловых систем.

### 03.11.2026 — аварийное прерывание копирования

- Linux-тест завершает процесс настоящим SIGKILL после создания внутреннего
  ZIP и до его шифрования. Обе отметки остаются `pending`, итоговая копия не
  публикуется, блокировка освобождается, автоматический повтор отвергается.
- Подтверждён остаток незашифрованного ZIP в защищённом временном каталоге.
  Безопасная очистка после аварии пока не реализована и остаётся препятствием
  для приёмки конфиденциальных архивов. Это один сценарий, не доказательство
  восстановления на всех этапах; шаги 53 и 70 остаются в работе.
- Проверка на Linux с Python 3.14: 119 тестов архивирования, блокировок и
  обновления прошли; платформенная приёмка и сценарий отключения питания
  не проводились.

## Журнал

### 03.11.2026 — связка writer-lock и зашифрованного снимка, шаг 53 частично

- Реальный синтетический worker блокирует защищённый архив обновления; после
  остановки worker архив создаётся и проверяется. Попытка повторного запуска
  согласованного писателя во время снимка отклоняется. Состояние systemd-группы
  в этом тесте имитируется, поэтому это не приёмка полного Linux-обновления.
- Отметка снимка дополнительно связана с `device:inode` файла lock; изменение
  этого идентификатора между повторами отклоняется, повторное использование inode
  не исключено. Клиент обновлён до 0.4.0. Несогласованные
  писатели, Docker, Windows и автоматическое обнаружение всех писателей не охвачены.

### 03.11.2026 — клиентский протокол писателей, шаг 53 частично

- `CooperativeWriterLock` доступен независимым продуктам в клиенте 0.3.0;
  установщик использует ту же реализацию. В тестовый продукт добавлен явный
  `--writer-lock` для worker, web и миграции, без изменения поведения по умолчанию.
- Изолированный Python с установленным wheel проверил работу реального worker
  без внутренних модулей установщика. Отдельно два писателя web/worker должны
  оба завершиться, прежде чем lock станет доступен архиватору. Несогласованные
  писатели, Docker, Windows и гарантии всех процессов пока не охвачены.

### 03.11.2026 — совместная блокировка писателей, шаг 53 частично

- Проверены отдельные процессы, SIGKILL писателя, конфликт доступа и реальный
  архив тестового worker. Другие писатели, Docker, Windows и сетевые файловые

### 02.11.2026 — отметка до внешнего действия

- Шаг 70 продолжается: экспериментальный `guard_effects=True` записывает в

  останавливается, а продолжение требует явного решения после проверки эффекта.
- Отметка теперь остаётся и во время повторного выполнения неопределённого шага.

- Это снижает риск незамеченного повтора, но не обнаруживает реальное состояние
  службы и не реализует самостоятельное восстановление порта. После записи
  отметки возможна остановка до начала действия; разрешение на повтор допустимо
  только при проверенной идемпотентности порта и согласованности системы.

### 02.11.2026 — неопределённый исход обновления

- Ядро `UpdatePlan` различает `EffectIndeterminate`: записывает признак в
  checkpoint и останавливается без автоматического перехода к откату. Обычный
  повтор не выполняет порты; после проверки вызывающий явно разрешает повтор
  через `run(resume_indeterminate=True)`. Старые checkpoint без поля совместимы.
- Тестовый systemd-мост передаёт неопределённость при ошибке группы служб.
  Подтверждённая обработка сбоев требует durable-реализации самого порта: в
  прежнем режиме при аварии до записи метки план не доказывает исход эффекта.
  Позднее добавлен опциональный режим предварительной отметки (см. выше).
- Автоматическое распознавание неизвестного исхода для любых сторонних портов,
  production systemd-мост и подключение операции возобновления к API отсутствуют.
- Python 3.14: 240 тестов `test_update_plan.py` и `test_ctl.py` прошли,
  включая проверку повторного запуска, повреждённого признака и совместимости
  прежних checkpoint. Временный контейнер применялся только для тестов.
- Повторная проверка на Python 3.14 с реальным user systemd: 4 теста прошли,
  включая оба сценария обновления/отката и обработку ошибок группы служб.
