# План доведения общего установочного модуля

Дата составления: 02.11.2026. Автор проекта: Serhii Khomenko · HomenS.AI.
Всего: 130 шагов; исходные номера 01–124 сохранены.

Уточнение владельца 02.11.2026: первая версия использует единый установочный
комплект для всех целевых систем. Разделение на минимальные комплекты не
обязательно. Профили ниже описывают совместимость продукта и выбор поведения,
а не требование выпускать отдельные пакеты. Нумерация и история сохранены.

Цель: самостоятельный общий модуль установки, проверенный на вымышленном
продукте без участия реальных проектов и зависимости от ИИ при работе.
Готовность означает выполнение требований и приёмку каждого заявленного профиля;
совместимость с реальными продуктами подтверждается отдельно после интеграции.

Статусы: `[ ]` — не начат; `[~]` — в работе; `[x]` — выполнен;
`[!]` — заблокирован. Шаг завершается только после проверки результата. При
изменении плана сохранять историю и корректировать число шагов прозрачно.

## Журнал

### 02.11.2026 — чтение состояния подготовки через API

- API 1.7 добавляет `fresh-status` для подписанного выпуска. Ответ показывает
  состояние связанного журнала и явно сообщает `completion_verified: false`;
  он не подтверждает готовность приложения или целостность размещённых файлов.
- Действия установки и возобновления через публичный API по-прежнему не
  объявлены: остаются незавершёнными контракт безопасного повтора, управление
  состояниями и платформенная приёмка. Шаги 109–113 остаются в работе.
- На Python 3.14 в Linux-контейнере прошли 115 тестов, включая CLI/Python,
  частичную подготовку, недоверенный ключ и изменение выпуска после записи
  журнала. Схема запроса отдельно проверена независимым валидатором.

### 02.11.2026 — фактический запуск тестового продукта

- Добавлена ограниченная loopback-проверка JSON с идентичностью продукта и
  версии, запретом прокси/перенаправлений и ограничением размера ответа.
- Сквозной тест использует подписанные выпуски, настоящие дочерние web/worker,
  SQLite-миграцию и шифрованные копии. Проверены успешное обновление и откат с
  повторным запуском старого выпуска после реального HTTP-отказа health.
- Управляющий адаптер только тестовый, не является службой ОС и не переживает
  аварийный рестарт. Динамический порт, Linux-контейнер и фиктивный продукт не
  являются приёмкой Windows/Docker или готовой установки. Шаг 84 начат.
- На Python 3.14 прошли 18 тестов продукта/обновления и отдельно 26 проверок
  модуля health и двух живых сценариев; наборы частично пересекаются.
  Дополнительная локальная проверка 25 сценариев health прошла на Python 3.11;
  она не является платформенной приёмкой проекта.

### 02.11.2026 — раннее возобновление и общая блокировка

- Формат журнала обновлён до 3: первоначальная подготовка и повторный запуск
  используют общую блокировку корня. Повтор после создания журнала, но до
  подготовки payload, заново проверяет пути и подпись и готовит выпуск.
- Журналы предыдущих экспериментальных форматов автоматически не принимаются;
  неполный `prepared`, чужие данные и повреждённая блокировка не удаляются.
  Восстановление после всех точек аварии и приёмка Windows ещё впереди.
- На Python 3.14 в Linux-контейнере прошли 48 тестов. Отдельно проверено
  принудительное завершение дочернего процесса сразу после записи журнала и
  последующее возобновление; это не имитация отключения питания.

### 02.11.2026 — ограниченное возобновление и сравнение проектов

- Шаг 63 начат: отдельный вызов продолжает подготовку после полного создания
