# Текстовый Linux bundle — шаг 8b

© 2026 Serhii Khomenko · HomenS.AI

`shared/linux_sh.py` использует stdlib и существующие валидатор v2,
`component_order`/`render_services`. Возвращает **только тексты**. Генератор
не выполняет shell/systemctl/useradd, не обращается к сети, не читает
окружение или файлы секретов. В этом шаге сценарии **сгенерированы, никогда
не исполнялись**. Linux/systemd и install/update/restore/rollback не приняты;
готового установщика нет.

## API и CLI

```python
from shared.linux_sh import render_linux
bundle = render_linux(manifest_v2, modes=("autonomous",),
                      install_root="/srv/example", user="homensai")
# dict filename -> UTF-8 text; без записи файлов.
```

```powershell
py -3.14 -B -m shared.ctl --manifest examples/rent.manifest.json render-linux --install-root /srv/demo --mode platform --output-dir build/linux-review --json
```

CLI записывает bundle в локальный `--output-dir` с LF/UTF-8. Нет исполнения,
выставления executable bit или установки служб. Существующие результаты не
перезаписываются. `--install-root` — текстовый абсолютный Linux-путь, даже если
рендер выполняется на Windows. Можно повторять `--mode`; mutual_exclusion и
зависимости проверяются существующим кодом. V1 отвергается. `--user` задаёт
отдельную непривилегированную учётную запись, по умолчанию `homensai`.
`--environment-file` меняет только публичный путь, значения секретов не принимает.

Bundle плоский: `install.sh`, `uninstall.sh`, `status.sh`, а для каждого
выбранного компонента `<product>-<component>.service` и
`<product>-<component>.service.override.conf`. Последний текст предназначен
для `/etc/systemd/system/<unit>.d/override.conf`. Все файлы bundle должны
оставаться вместе для будущего ручного рассмотрения install.sh.

## Содержимое текстов

`install.sh` содержит root-проверку, создание системной группы/пользователя
без home, с `/usr/sbin/nologin`, отказ от существующего UID 0, подготовку
каталогов и запись units/override из bundle. Код/runtime/services имеют root
владельца и 0755; data/backup/config — отдельного пользователя и 0700.
Относительные пути v2 привязаны к install_root. Payload и Python/runtime
не поставляются, зависимости не устанавливаются, миграции не выполняются.
В install.sh нет systemctl: он не reload/enable/start службы.

Unit сохраняет after/requires, restart delay/max/window, loopback-настройки
и argv существующего рендера. Override задаёт `User`, `Group`, `UMask=0077`,
`NoNewPrivileges=true`, обязательный `EnvironmentFile` без префикса «-».
`PassEnvironment` удалён: источник секретов — только внешний файл.

По умолчанию EnvironmentFile расположен в `/etc/<product_id>/service.env`,
его каталог root:root/0700, файл root:root/**0600**. systemd читает его как
менеджер до перехода к служебному пользователю. Новый файл содержит лишь
комментарии `# NAME` для service-контекста, без `NAME=` и без значений.
Admin-only имена исключены. Существующее содержимое не читается/не перезаписывается
сценарием; текст содержит chown/chmod для восстановления режима. Символическая
ссылка или не обычный файл в конечном пути приводят к отказу. Нет source,
cat, set -x, печати Environment или журнальных строк.

Значения должен отдельно предоставить администратор через защищённый канал;
пустая заготовка не выполняет required/same_value и не готова к запуску.
Согласованность admin/service `BACKUP_PASSWORD` генератор не проверяет.

`uninstall.sh` содержит stop/disable в обратном порядке зависимостей,
удаление только конкретных units/override и daemon-reload. При ошибке stop
сценарий прекращается. Программа, выпуски, runtime, данные, архивы, секреты
и учётная запись сохраняются. Рекурсивного удаления нет. `status.sh` запрашивает
только `Id,LoadState,ActiveState,SubState`, отдельно is-active, возвращает 1,
если компонент не активен; это статус systemd, не doctor и не health продукта.

## Безопасность строк и границы

Shell-аргументы закодированы `shlex.quote`, фиксированный printf использует `%s`.
Пользователь ограничен `[a-z_][a-z0-9_-]{0,30}`, root запрещён; идентификаторы
берутся из валидатора. Shell-команд продукта и eval нет. Для systemd используются
кавычки/C-escaping, `%%` для literal specifiers и `$$` для argv; в пути директивы
`$` остаётся literal. Непредставимые executable/prefix, относительный executable
со slash, `$` в executable, управляющие/невалидные Unicode-символы запрещены.
Пробелы, кириллица, кавычки, shell-метасимволы в публичных путях/аргументах
проверены как текст, без исполнения.

Пути только POSIX, без `..`, `.`, UNC, backslash/drive/ADS; корень ФС запрещён.
Каталоги установки не пересекаются между собой, с каталогом EnvironmentFile
или `/etc/systemd/system`. EnvironmentFile требует отдельный каталог минимум
вроде `/etc/example` и не может попасть внутрь app/releases/данных/config.
Это лексические проверки: генератор не stat/resolve целевую Linux-ФС.
Ссылки/гонки родительских каталогов, hardlinks, чужие существующие службы/
учётные записи, фактические права и поведение systemd требуют отдельной приёмки
на подготовленной машине. Сценарии не являются транзакцией с rollback или
средством безопасного изменения произвольной враждебной ФС. Все публичные строки
входа должны быть без секретов: распознать пароль внутри разрешённого argv нельзя.

StartLimitBurst systemd считает запуски, а не точные падения за скользящие
10 минут. Чистые doctor/crash-loop/rate limiter — в [DOCTOR.md](DOCTOR.md);
их stop/уведомления к systemd ещё не подключены. Свежесть heartbeat/архива,
шифрование, миграции и продуктовые health hooks здесь не исполняются.

## Проверки

`tests/test_linux_sh.py` использует tmp_path, статические golden-файлы в
`tests/golden/linux`, hostile inputs, обе формы путей, порядок зависимостей,
отказ при пересечениях, чистоту API, CLI без перезаписи и синтетические секреты
только в тестовом окружении. Реальные процессы запрещены fixture нового набора,
сеть запрещена общей fixture. Golden-файлы — рассмотренные тексты для
публичного Rent-примера/platform, не исполненные сценарии.

Контейнерная проверка из CLAUDE.md не выполняется: прямое задание запрещает
внешние службы. Ни Docker, ни Linux/systemd в этом шаге не запускались.

Полный локальный pytest выполняется на Windows/Python 3.14 / pytest 9.1.1
через прежний документированный WorkspaceTemps: обычный mkdir внутри worktree,
без изменения ACL и без исключения файловых сценариев. Bytecode, кэш и
сторонние plugins отключены. Точная команда:

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
$env:PYTHONIOENCODING = 'utf-8'
@'
from pathlib import Path
import uuid
import pytest
class WorkspaceTemps:
    @pytest.fixture
    def tmp_path(self):
        path = Path.cwd() / 'build' / 'step8b-pytest' / uuid.uuid4().hex
        path.mkdir(parents=True)
        return path
raise SystemExit(pytest.main(['-q', '-r', 's', '-p', 'no:cacheprovider', '-p', 'no:tmpdir'], plugins=[WorkspaceTemps()]))
'@ | py -3.14 -B - | Tee-Object -FilePath build/step8b-pytest-output.txt
exit $LASTEXITCODE
```
